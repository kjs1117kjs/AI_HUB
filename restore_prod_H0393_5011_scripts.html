삭제 상품 복구용 두 SQL 스크립트의 설명과 소스 복사 버튼

1. 삭제 상품 복구용 정보 수집 DBMS_OUTPUT 텍스트
restore_prod_H0393_5011.sql · SBPORA · 조회 전용
구성
[0]운영/로그 테이블 잔존 건수 — 운영 0, 로그 1건 이상이면 정상적으로 삭제된 상태
[1]로그 3종 타임라인 (PROC_DT / PROC_FG: I 등록, U 수정, D 삭제)
[2]화면 입력표 — 삭제 직전 I/U 행을 컬럼 [한글코멘트] : 값 → 코드명 형식으로 보여줌. 감사컬럼과 NULL은 제외
[2']삭제행(A)과 직전행(B) 비교 — 감사컬럼 말고 다른 차이가 없으면 D 행을 그대로 써도 됨
[3]부속 테이블 — 바코드, 판매시간, 거래처, 단가이력, 옵션, 사이드, ERP 매핑 등
[4]매장 전파분 TB_MS_PRODUCT* 잔존 여부와 매장별 건수 [4-0]
[5]컬럼 사전과 로그 전용 컬럼 [5-1]
실행
F5(스크립트 실행)로 돌립니다. F9로 한 문장씩 실행하면 DBMS_OUTPUT 결과가 보이지 않습니다.
2. 재등록 입력표 — HTML 출력판 SPOOL → .html
restore_prod_H0393_5011_html.sql · 출력 E:\_work\_work\restore_prod_H0393_0000000005011.html
페이지 구성
카드상품코드, 상품명, 판매단가
1~3상품기본, 부가정보, 판매가 입력표 — 항목명은 한글 코멘트로, 삭제 직전에 바뀐 값에는 노란 "직전 수정" 배지를 붙여 이전 값과 함께 표시
4부속 및 매장 데이터 잔존 건수 (0건인 테이블은 한 줄로 묶음)
!확인할 점 — 삭제자·삭제시각, D행과 직전행 불일치, 코드 재채번, 매장 전파
T로그 타임라인 (삭제 행은 빨간색)
실행
sqlplus로 실행할 때는 먼저 set NLS_LANG=KOREAN_KOREA.AL32UTF8을 설정하세요. 설정하지 않으면 PLS-00103 오류가 납니다. SQL Developer에서는 F5로 실행하면 되고, SPOOL이 동작하지 않으면 출력창 내용을 .html로 저장하세요.
화면 재등록 시 주의
1. 화면에서 저장하면 FN_GET_PROD_CD_MAX가 새 코드를 채번합니다. 기존 매출, 재고, 단가이력은 옛 코드(0000000005011)에 그대로 남습니다.
2. TB_HQ_PRODUCT_BARCD에 바코드가 남아 있으면 등록할 때 중복될 수 있습니다. [3-1]을 먼저 확인하세요.
3. 저장하면 SP_HQ_PRODUCT_I, CLASS_I02, SALE_PRICE_I2를 통해 매장으로 자동 전파됩니다. 매장에 옛 코드가 남아 있으면 옛 코드와 새 코드가 둘 다 존재하게 됩니다.
