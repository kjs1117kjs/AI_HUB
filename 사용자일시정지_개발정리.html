일시정지 / 해제 처리

  • 확인 팝업에서 비고(필수)와 관리자 확인 비밀번호 입력

5자동 일시정지 — SP_JOB_AUTO_PAUSE_IUD01

6로그인 세션 즉시 차단

USER_STAT_FG='50'은 새 로그인만 막기 때문에, 이미 로그인된 세션(봇 포함)을 끊기 위해 모든 요청이 거치는 FN_GET_MENU_CHK_YN2에 확인을 추가했습니다.

반환의미AuthenticationInterceptor 처리
Y허용그대로 진행
N메뉴 제한 (기존)"메뉴 사용 제한" 후 메인화면
P일시정지 (신규)세션 삭제 → 화면: alert 후 최상위 창 로그인 / AJAX: SESSION_EXFIRE JSON
'N'이 아닌 'P'를 쓰는 이유 — 'N'으로 처리하면 메인화면 이동 → 메인화면도 'N' → alert가 무한 반복됩니다.
  • 함수 맨 앞 STEP 00: TB_WB_USER_INFO PK 1건 조회 후 50이면 즉시 'P' 반환 (이후 판정·이력·딜레이 생략)
  • 관리자 가상로그인 세션은 차단하지 않음 (vUserId 존재 시)
  • 배포 순서 무관: 함수만 먼저 반영되면 기존 인터셉터는 'P'를 허용으로 처리 (영향 없음)

8자동 해제 Job — SP_JOB_CHK_LOGIN_IUD01

  • USER_ID별 최신 이력이 일시정지(P, 반영 Y), 30분 경과, 현재 상태 50인 사용자를 00으로 해제
  • 해제 이력 PROC_FG='R', 처리자 SP_JOB_CHK_LOGIN, 스냅샷은 정지 당시 값 복사
  • 최신 이력이 R이면 대상 아님 → 본인·관리자가 이미 푼 계정 중복 처리 없음
  • 시험 기록(T)은 정지되지 않은 사용자에게만 남으므로 판정에 영향 없음

14권한 (GRANT)

프로시저·함수 안의 SQL은 Role로 받은 권한을 인정하지 않습니다. 웹 쿼리에서 잘 조회되던 테이블도 프로시저 컴파일 시 ORA-00942가 날 수 있으며, 소유자가 SBPORA에게 직접 GRANT해야 합니다.
-- 프로시저 사용 객체의 직접 권한 점검
SELECT  O.OBJECT_NAME, O.OWNER, O.OBJECT_TYPE
,       CASE WHEN O.OWNER = USER THEN '본인 소유 (OK)'
             WHEN EXISTS (SELECT 1 FROM USER_TAB_PRIVS P
                          WHERE P.OWNER = O.OWNER AND P.TABLE_NAME = O.OBJECT_NAME
                          AND P.PRIVILEGE = 'SELECT') THEN '직접 GRANT (OK)'
             ELSE '★ 직접 권한 없음 — GRANT 필요'
        END AS PRIV_CHK
FROM    ALL_OBJECTS O
WHERE   O.OBJECT_NAME IN ( 'TB_MONITOR_ALARM', 'TB_WB_LOGIN_HIST_BLOCK', 'TB_WB_USER_INFO'
                         , 'TB_CM_EMPLOYEE', 'TB_CM_NMCODE', 'TB_WB_USER_PAUSE_HIST'
                         , 'SEQ_TB_WB_USER_PAUSE_HIST' )
AND     O.OBJECT_TYPE IN ('TABLE', 'VIEW', 'SEQUENCE')
ORDER BY 1;

-- 소유자 또는 DBA 실행
GRANT SELECT         ON <소유자>.TB_MONITOR_ALARM TO SBPORA;
GRANT INSERT         ON <소유자>.TB_MONITOR_ALARM TO SBPORA;   -- 알림 사용 시

-- 재컴파일 · 오류 확인
ALTER PROCEDURE SBPORA.SP_JOB_AUTO_PAUSE_IUD01 COMPILE;
SELECT * FROM USER_ERRORS WHERE NAME = 'SP_JOB_AUTO_PAUSE_IUD01';

시노님이 없으면 프로시저 안의 TB_MONITOR_ALARM(4곳: CHK_RAW, LGN_RAW, ME_RAW·URL_RAW, PRC_ALARM)을 <소유자>.TB_MONITOR_ALARM으로 바꿔야 합니다.

15운영 · 모니터링

운영 절차

1. 시험 운영 (1~2주)
전 항목 T 모드. 걸린 사용자 확인 → 오탐은 화이트리스트 등록 또는 임계치 상향
2. 항목별 실제 전환
오탐이 적은 G1·G2부터 하나씩 Y로 전환 후 재컴파일
3. 알림 · 고도화
알림 사용, B3·B4·B5 검증, 반복 위반 단계 강화 검토

    ,   start_date      => SYSTIMESTAMP
    ,   repeat_interval => 'FREQ=MINUTELY;INTERVAL=5'

조회 쿼리

-- 자동 판정 이력 (최근순)
SELECT  PROC_DT, USER_ID, PROC_FG, RESULT_FG, RISK
,       MIN5_REAL, ME_REAL, CHK_IP_CNT, CHK_LAST_IP, IP_HIT, REMARK, SUMMARY_TXT
FROM    TB_WB_USER_PAUSE_HIST
WHERE   PROC_ID = 'SP_JOB_AUTO_PAUSE'
ORDER BY PROC_DT DESC;

-- 항목별 · 일자별 걸린 인원 (임계치 조정용)
SELECT  SUBSTR(PROC_DT, 1, 8) AS PROC_DATE
,       SUM(CASE WHEN REMARK LIKE '%G1%' THEN 1 ELSE 0 END) AS G1
,       SUM(CASE WHEN REMARK LIKE '%G2%' THEN 1 ELSE 0 END) AS G2
,       SUM(CASE WHEN REMARK LIKE '%B1%' THEN 1 ELSE 0 END) AS B1
,       SUM(CASE WHEN REMARK LIKE '%B2%' THEN 1 ELSE 0 END) AS B2
,       SUM(CASE WHEN REMARK LIKE '%B3%' THEN 1 ELSE 0 END) AS B3
,       SUM(CASE WHEN REMARK LIKE '%B4%' THEN 1 ELSE 0 END) AS B4
,       SUM(CASE WHEN REMARK LIKE '%B5%' THEN 1 ELSE 0 END) AS B5
,       COUNT(DISTINCT USER_ID) AS USER_CNT
FROM    TB_WB_USER_PAUSE_HIST
WHERE   PROC_ID = 'SP_JOB_AUTO_PAUSE'
GROUP BY SUBSTR(PROC_DT, 1, 8)
ORDER BY 1 DESC;

-- 현재 일시정지 중인 사용자와 마지막 정지 이력
SELECT  U.USER_ID, U.MOD_DT, U.MOD_ID, H.PROC_DT, H.PROC_ID, H.REMARK
FROM    TB_WB_USER_INFO U
LEFT OUTER JOIN (
        SELECT  X.*, ROW_NUMBER() OVER (PARTITION BY X.USER_ID ORDER BY X.PROC_DT DESC, X.PAUSE_SEQ DESC) RN
        FROM    TB_WB_USER_PAUSE_HIST X
        WHERE   X.PROC_FG = 'P'
        ) H ON H.USER_ID = U.USER_ID AND H.RN = 1
WHERE   U.USER_STAT_FG = '50'
ORDER BY H.PROC_DT DESC;

-- 본인 해제 이력
SELECT  PROC_DT, USER_ID, RESULT_FG, SUMMARY_TXT
FROM    TB_WB_USER_PAUSE_HIST
WHERE   PROC_FG = 'R' AND REMARK = '로그인 화면 본인 숫자확인 해제'
ORDER BY PROC_DT DESC;

  • 자동 정지 Job · 자동 해제 Job 등록 (5분 주기)
  • 화이트리스트 252 초기 등록 (업무상 대량 조회 계정 · 사내 IP), 해외 근무자 TB_CM_IP_ALLOW
  • 메시지 login.pw.find.suspend 문구 · 신규 메시지 키 배포
  • userMenuChkYn / FN_GET_MENU_CHK_YN2의 다른 호출처(모바일 등) 확인 — 'P'를 'N'으로만 판단하면 통과됨
  • JS 캐시 버전(?ver=) 갱신
