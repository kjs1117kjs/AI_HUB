SBPORA · GEOIP MONTHLY RELOAD

GeoIP 재적재 자동화 — 실행 방법 & 기능 설명

월간 GeoIP 재적재(A/B 무중단 스위칭)를 두 가지 방식으로 — 평소엔 DB 서버의 cron이 자동으로 돌고, 필요할 때 PC 웹 콘솔에서 버튼으로 수동 실행합니다.

A1 · 개요 — 무엇을 구축하나

DB 서버 soldb1의 /home/oranx/kjscheck/에 bash 스크립트 geoip_auto.sh를 설치하고, cron이 매월 1일·14일 06:30에 실행하게 합니다. 파이썬 없이 서버에 원래 있는 도구(curl · unzip · awk · sqlplus · sqlldr)만 사용합니다.

동작: 다운로드 → 변환 → 대기 테이블 적재 → 게이트 5개(G1~G5) → 전부 통과한 경우에만 시노님 스위치. 게이트를 하나라도 못 넘으면 스위치 없이 중단하고 로그만 남기므로 서비스에는 영향이 없고, 다음 회차가 자연스러운 재시도가 됩니다.

geoip_auto.sh 재적재 스크립트 본체. 원본 검증값: 262줄 / md5 07cef72b9aa9fc9f1e268c2854318244
geoip_auto.b64 전송용 base64 사본. 붙여넣기로 옮겨도 깨지지 않는 형식 — 구축 시 이것으로 설치.
geoip.conf 설정. LICENSE_KEY · DB 계정 · ORACLE_HOME · ORACLE_SID(SBP) · MIN_ROWS. chmod 600 유지.
logs/ 실행 이력. 회차마다 auto_날짜_OK.log 또는 _FAIL.log, cron 전체 출력은 cron.log에 누적.

A2 · 구축 전 사전 검증 — 이게 다 되어야 함

서버(oranx 계정)에서 아래 4개를 확인합니다. 하나라도 안 되면 구축 전에 먼저 해결해야 합니다.

① 필수 도구 — 6개 전부 경로가 나와야 함
which curl unzip awk sort sqlplus sqlldr
② 인터넷 (MaxMind) — HTTP/1.1 302 면 정상
curl -sI --max-time 10 https://download.maxmind.com | head -1
③ Oracle 인스턴스 — ora_pmon_SBP 가 보여야 함 (SID=SBP)
ps -ef | grep pmon | grep -v grep
df -h /home                          # 폴더 공간 — 수백 MB면 충분
④ DB 오브젝트 — sqlplus SBPORA 접속 후, 시노님 1건 + 테이블 2건 나와야 함
SELECT synonym_name, table_name FROM user_synonyms WHERE synonym_name = 'TB_CM_GEOIP_RANGE';
SELECT table_name FROM user_tables WHERE table_name IN ('TB_CM_GEOIP_RANGE_A','TB_CM_GEOIP_RANGE_B');
이 외에 MaxMind 라이선스 키가 준비돼 있어야 합니다 (구축 가이드 2장 참고 — maxmind.com 계정에서 발급). sqlplus 접속 자체가 안 되면 계정/비밀번호부터 확인.

A3 · 구축 — 파일 설치

vi에 붙여넣기 금지 — 자동 들여쓰기가 파일을 변형시킵니다. base64 방식으로 설치하고 md5로 검증합니다.

1) 폴더 준비
mkdir -p /home/oranx/kjscheck/logs
cd /home/oranx/kjscheck
2) 스크립트 설치 — PC에서 geoip_auto.b64 를 메모장으로 열어 전체 복사한 뒤
cat > geoip_auto.b64
# → 마우스 우클릭으로 붙여넣기 → Enter 한 번 → Ctrl+D
base64 -d geoip_auto.b64 > geoip_auto.sh
md5sum geoip_auto.sh
# → 07cef72b9aa9fc9f1e268c2854318244  이어야 함 (다르면 다시)
chmod +x geoip_auto.sh
3) 설정 파일 생성 — 아래를 통째로 붙여넣고, 키·비밀번호만 실제 값으로
cat > geoip.conf << 'EOF'
LICENSE_KEY=여기에_MaxMind_라이선스_키
DB_USER=SBPORA
DB_PASS=여기에_비밀번호
ORACLE_HOME=/oracle/oranx/product/19.12.0.0
ORACLE_SID=SBP
MIN_ROWS=300000
EOF
vi geoip.conf                # LICENSE_KEY, DB_PASS 실제 값 입력
grep -c $'\r' geoip.conf     # 0 이어야 함 (CR 오염 확인)
chmod 600 geoip.conf         # 비밀번호 보호
WinSCP를 쓸 수 있으면 base64 대신 파일을 직접 끌어다 놓아도 됩니다 — 단 전송 모드를 Binary로. 어느 방식이든 설치 후 md5 일치 확인이 필수입니다.

A4 · 첫 실행 검증 (스위치 없이) + 첫 스위치

1) 테스트 실행 — 서비스 영향 0
cd /home/oranx/kjscheck
./geoip_auto.sh --no-switch

정상이면 이렇게 진행됩니다 (수 분): DB 접속 확인: DB_OK → ① 다운로드 → ② 변환 (약 56만 건) → G1·G2 통과 → ③ 대기 테이블 적재 → G3 통과 → ④ G4 통과 → 통계수집 → G5 통과 → 마지막 줄에 수동 스위치 SQL 출력.

중간의 stty: 부적절한 ioctl 메시지는 셸 환경설정의 무해한 경고이니 무시하세요 (cron 실행에서는 안 나옵니다).

2) 첫 스위치는 수동으로 — sqlplus 에서
-- 테스트 출력 마지막에 찍힌 SQL 그대로 (대상 테이블명 확인)
CREATE OR REPLACE SYNONYM TB_CM_GEOIP_RANGE FOR TB_CM_GEOIP_RANGE_B;

-- 확인: Y 와 N 이 나와야 정상
SELECT IS_KOREA_IP('223.62.180.1'), IS_KOREA_IP('8.8.8.8') FROM DUAL;

-- 건수 확인
SELECT COUNT(*) FROM TB_CM_GEOIP_RANGE;
첫 회만 이렇게 눈으로 확인하며 넘기고, 이후부터는 cron이 스위치까지 무인으로 합니다.

A6 · 잘 돌았는지 확인하는 법

매월 1일·14일 이후 아무 때나 아래로 확인합니다. 파일명 끝이 OK면 스위치까지 성공, FAIL이면 실패(시노님 미변경), LOADED는 --no-switch로 적재만 한 것.

서버에서 — 로그 확인
ls -lt /home/oranx/kjscheck/logs/ | head -5     # 최근 회차 결과 (OK/FAIL)
tail -30 /home/oranx/kjscheck/logs/cron.log     # 최근 실행 상세 로그
DB에서 — 실제 반영 확인
-- 지금 어느 테이블(A/B)이 활성인지
SELECT table_name FROM user_synonyms WHERE synonym_name = 'TB_CM_GEOIP_RANGE';

-- 건수 (재적재 시 매월 소폭 변동, 50만~60만대)
SELECT COUNT(*) FROM TB_CM_GEOIP_RANGE;

-- 판정 동작 (Y / N 이면 정상)
SELECT IS_KOREA_IP('223.62.180.1'), IS_KOREA_IP('8.8.8.8') FROM DUAL;
활성 테이블은 회차마다 A ↔ B로 번갈아 바뀌는 것이 정상입니다 (무중단 스위칭의 원리).

A7 · 수동 실행 (서버에서 바로 돌리기)

스케줄과 무관하게 아무 때나 실행할 수 있습니다. 이미 실행 중이면 락 파일이 중복 실행을 막습니다.

A8 · 중지 / 재개

중지: crontab -e로 열어 해당 줄 맨 앞에 #을 붙이고 저장하면 그 회차부터 돌지 않습니다.

재개: 같은 방법으로 #을 지우면 됩니다. 오래 중지했다가 재개하는 경우, 재개 직후 A7의 수동 실행을 한 번 돌려 데이터를 최신으로 맞춰두는 것을 권장합니다.

중지 상태 예시
#30 6 1,14 * * /home/oranx/kjscheck/geoip_auto.sh >> /home/oranx/kjscheck/logs/cron.log 2>&1
주의: crontab -r은 이 줄만이 아니라 계정의 crontab 전체를 삭제합니다. 중지는 반드시 # 주석으로.

A9 · 실패했을 때

실패 회차는 logs/auto_날짜_FAIL.log로 남고, 로그 끝의 "■ 중단: ..." 줄에 어느 게이트에서 왜 멈췄는지 적혀 있습니다. 실패해도 시노님은 그대로라 서비스는 정상이고, 다음 회차(1일 실패 → 14일)가 자동 재시도입니다. 급하면 A7로 수동 재실행하면 됩니다.

스위치까지 된 뒤 판정이 이상하면 이전 테이블로 즉시 원복합니다 (완료 로그 맨 아래에 그 회차의 롤백 SQL이 항상 찍혀 있습니다):

롤백 (무중단)
CREATE OR REPLACE SYNONYM TB_CM_GEOIP_RANGE FOR 이전테이블;   -- 예: TB_CM_GEOIP_RANGE_A

A10 · 서버 쪽 문제 해결

증상조치
syntax error near unexpected token — 스크립트가 실행 초반에 죽음파일 전송 중 변형(vi 붙여넣기의 자동 들여쓰기, CRLF). vi에 붙여넣지 말 것. A3의 base64 방식으로 재설치 후 md5 검증: md5sum geoip_auto.sh → 07cef72b9aa9fc9f1e268c2854318244
ORA-01034: ORACLE not availableconf의 ORACLE_SID가 실제 인스턴스와 다름. ps -ef | grep pmon으로 확인 — 이 서버는 SBP(oranx 소유)가 맞고, TSP는 다른 DB.
다운로드 실패 (HTTP 401)MaxMind 라이선스 키 만료/오류 — 키 재발급 후 conf 수정. 급하면 CSV를 수동으로 폴더에 두고 --skip-download.
"이미 실행 중입니다 (락...)"실제 실행 중이면 대기. 비정상 종료 잔재라면 6시간 뒤 자동 무시되며, 즉시 지우려면 rm /home/oranx/kjscheck/.geoip_auto.lock
stty: 부적절한 ioctl 경고셸 환경설정에서 나오는 무해한 경고 — 무시. cron 실행에서는 나오지 않습니다.

1 · 핵심 설계 — 왜 안전한가

시노님 스위치 전의 모든 작업은 대기 테이블에서만 일어납니다. 다운로드·변환·적재·검증 어느 단계가 실패해도 서비스는 기존 테이블로 계속 동작하고, 스크립트는 그냥 중단 + 로그만 남깁니다.

위험한 순간은 시노님 스위치 하나뿐이라, 그 앞에 게이트 5개(G1~G5)를 두고 전부 통과해야만 스위치 버튼이 활성화됩니다. 스위치 후 문제가 보이면 [롤백] 버튼으로 이전 테이블에 즉시 원복됩니다 (역시 무중단).

①
다운로드
MaxMind zip 수령 · 압축 해제
②
변환 · 로컬 검증
G1 · G2
CIDR→숫자 + 국가 조인
③
DB 적재
G3
대기 테이블 자동 판별 · 배치 INSERT
④
검증 · 통계
G4 · G5
DBMS_STATS + 판정 리허설
⑤
시노님 스위치
사람이 버튼으로 확정 · 무중단
기존 수작업 대비 sqlldr이 사라졌습니다 — 배치 INSERT로 대체해서 ctl 파일 2벌, geoip.bad 확인, DIRECT=TRUE 인덱스 UNUSABLE 리빌드가 전부 필요 없습니다. "지금 A였나 B였나"도 시노님을 읽어 자동 판별합니다.

2 · 구성 파일

전부 E:\_work\GeoLite2 한 폴더에 둡니다.

start.bat 더블클릭 실행기. python·설정 파일을 확인하고 콘솔 서버를 띄운 뒤 브라우저를 자동으로 엽니다. CP949 인코딩이라 한글 Windows cmd에서 바로 동작.
geoip_console.py 웹 콘솔 서버. 127.0.0.1:8765 로만 뜨는 로컬 서버 — 본인 PC에서만 접속 가능. 화면의 버튼·배지·실시간 로그를 제공하며, 실제 재적재 로직이 여기 들어 있습니다.
geoip_config.json 설정 파일 (직접 생성, 1회). 라이선스 키·DB 접속 정보·작업 폴더. 아래 3장 참고.
logs\ 실행 이력. 매 세션의 로그가 console_날짜_OK / _FAIL / _ROLLBACK.log 로 저장됩니다.

3-1. 패키지 설치

3-2. geoip_config.json 생성

sqlldr 쓸 때의 접속 문자열 USER/PASSWORD@HOST:PORT/SERVICE에서 값을 나눠 넣으면 됩니다. 경로 구분자는 / 권장.

geoip_config.json
{
  "license_key": "MaxMind 라이선스 키",
  "db_user":     "SBPORA",

비밀번호를 파일에 남기기 싫으면 "db_password": "ENV" 로 적고, bat 파일 안의 rem set GEOIP_DB_PASSWORD=... 줄의 rem을 지우고 값을 넣으세요 (또는 실행 전 set GEOIP_DB_PASSWORD=...).

4 · 실행 방법 — 웹 콘솔

start.bat 더블클릭 → 검은 창이 뜨고 브라우저가 자동으로 http://127.0.0.1:8765 를 엽니다. 검은 창은 서버라서 닫으면 콘솔도 꺼집니다 — 작업 끝날 때까지 그대로 두세요.

월간 재적재의 일반 순서:

  • [▶ 전체 실행] 클릭 — ①~④가 자동으로 진행되고 로그가 실시간으로 흐릅니다 (수 분).
  • ④까지 전부 완료가 되면 요약줄에 "기존 N건 → 신규 M건"이 뜨고 ⑤ [스위치] 버튼이 활성화됩니다.
  • 숫자를 확인하고 [스위치] 클릭 → 확인창 → 전환 완료. 스위치 후 IS_KOREA_IP 동작까지 자동 확인해 줍니다.

zip을 이미 수동으로 받아 CSV를 폴더에 풀어뒀다면 [다운로드 생략] 체크박스를 켜고 실행하면 ①이 로컬 파일을 사용합니다.

5 · 콘솔 화면 기능

요소설명
[▶ 전체 실행]①~④를 순서대로 자동 진행. ⑤ 스위치는 절대 자동으로 하지 않습니다 — 항상 사람이 확정.
단계 카드 ①~⑤각 단계를 개별 실행할 수도 있습니다. 순서를 건너뛰면 "③을 먼저 실행하세요"라고 로그에 안내. 상태 배지: 대기 진행중 완료 실패

7 · 문제 해결

증상조치
bat 더블클릭 시 한글이 깨지고 "내부 또는 외부 명령…이 아닙니다" 연발구버전 bat(UTF-8 저장본)의 인코딩 문제. CP949로 저장된 최신 bat로 교체하면 해결.
ModuleNotFoundError: oracledb (③에서 실패)pip install oracledb 후 ③부터 다시 실행. 앞 단계 결과는 유지됩니다.
"geoip_config.json 이 없습니다"3-2 참고해 같은 폴더에 설정 파일 생성.
① 다운로드 실패 HTTP 401라이선스 키 오류 — MaxMind 계정에서 키 재발급. 급하면 브라우저로 zip 수동 다운로드 → 압축 해제 → [다운로드 생략] 체크 후 진행.
G5 실패 — 조회 0.5s 초과통계수집이 안 먹었거나 인덱스 문제. ④를 한 번 더 실행 (통계 재수집). 반복되면 SELECT index_name, status FROM user_indexes WHERE table_name LIKE 'TB_CM_GEOIP_RANGE_%' 확인.
스위치 후 판정이 이상함[롤백] 버튼 — 이전 테이블로 즉시 원복. 콘솔을 이미 껐다면 SQL로: CREATE OR REPLACE SYNONYM TB_CM_GEOIP_RANGE FOR 이전테이블;
브라우저가 안 열림 / 페이지 접속 안 됨검은 창(서버)이 살아있는지 확인 후 주소창에 http://127.0.0.1:8765 직접 입력. 8765 포트를 다른 프로그램이 쓰면 geoip_console.py 상단 PORT 변경.
다른 PC에서 접속하고 싶음보안상 의도적으로 막혀 있습니다 (127.0.0.1 전용). DB 계정 정보가 있는 콘솔이므로 본인 PC에서만 사용.
기억할 것 하나: ⑤ 스위치 전에는 무엇이 실패해도 서비스에 영향이 없습니다. 에러가 나면 당황하지 말고 로그 확인 → 해당 단계부터 재실행하면 됩니다.
