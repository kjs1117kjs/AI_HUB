SBPORA · GEOIP MONTHLY RELOAD

GeoIP 재적재 자동화 — 실행 방법 & 기능 설명

월간 GeoIP 재적재(A/B 무중단 스위칭)를 버튼 클릭으로. 수작업 8단계가 [전체 실행] 한 번 + 스위치 확인 한 번으로 줄었습니다.

1 · 핵심 설계 — 왜 안전한가

시노님 스위치 전의 모든 작업은 대기 테이블에서만 일어납니다. 다운로드·변환·적재·검증 어느 단계가 실패해도 서비스는 기존 테이블로 계속 동작하고, 스크립트는 그냥 중단 + 로그만 남깁니다.

위험한 순간은 시노님 스위치 하나뿐이라, 그 앞에 게이트 5개(G1~G5)를 두고 전부 통과해야만 스위치 버튼이 활성화됩니다. 스위치 후 문제가 보이면 [롤백] 버튼으로 이전 테이블에 즉시 원복됩니다 (역시 무중단).

2 · 구성 파일

전부 E:\_work\GeoLite2 한 폴더에 둡니다.

start.bat 더블클릭 실행기. python·설정 파일을 확인하고 콘솔 서버를 띄운 뒤 브라우저를 자동으로 엽니다. CP949 인코딩이라 한글 Windows cmd에서 바로 동작.
geoip_console.py 웹 콘솔 서버. 127.0.0.1:8765 로만 뜨는 로컬 서버 — 본인 PC에서만 접속 가능. 화면의 버튼·배지·실시간 로그를 제공하며, 실제 재적재 로직이 여기 들어 있습니다.
geoip_config.json 설정 파일 (직접 생성, 1회). 라이선스 키·DB 접속 정보·작업 폴더. 아래 3장 참고.
logs\ 실행 이력. 매 세션의 로그가 console_날짜_OK / _FAIL / _ROLLBACK.log 로 저장됩니다.

3 · 사전 준비 (최초 1회)

3-1. 패키지 설치

PowerShell / cmd
cd E:\_work\GeoLite2
python --version          :: 3.8 이상이면 OK
pip install oracledb requests

3-2. geoip_config.json 생성

sqlldr 쓸 때의 접속 문자열 USER/PASSWORD@HOST:PORT/SERVICE에서 값을 나눠 넣으면 됩니다. 경로 구분자는 / 권장.

geoip_config.json
{
  "license_key": "MaxMind 라이선스 키",
  "db_user":     "SBPORA",
  "db_password": "비밀번호",
  "db_dsn":      "HOST:PORT/SERVICE",
  "work_dir":    "E:/_work/GeoLite2",
  "min_rows":    300000
}
비밀번호를 파일에 남기기 싫으면 "db_password": "ENV" 로 적고, bat 파일 안의 rem set GEOIP_DB_PASSWORD=... 줄의 rem을 지우고 값을 넣으세요 (또는 실행 전 set GEOIP_DB_PASSWORD=...).

4 · 실행 방법 — 웹 콘솔

start.bat 더블클릭 → 검은 창이 뜨고 브라우저가 자동으로 http://127.0.0.1:8765 를 엽니다. 검은 창은 서버라서 닫으면 콘솔도 꺼집니다 — 작업 끝날 때까지 그대로 두세요.

월간 재적재의 일반 순서:

  • [▶ 전체 실행] 클릭 — ①~④가 자동으로 진행되고 로그가 실시간으로 흐릅니다 (수 분).
  • ④까지 전부 완료가 되면 요약줄에 "기존 N건 → 신규 M건"이 뜨고 ⑤ [스위치] 버튼이 활성화됩니다.
  • 숫자를 확인하고 [스위치] 클릭 → 확인창 → 전환 완료. 스위치 후 IS_KOREA_IP 동작까지 자동 확인해 줍니다.

zip을 이미 수동으로 받아 CSV를 폴더에 풀어뒀다면 [다운로드 생략] 체크박스를 켜고 실행하면 ①이 로컬 파일을 사용합니다.

5 · 콘솔 화면 기능

요소설명
[▶ 전체 실행]①~④를 순서대로 자동 진행. ⑤ 스위치는 절대 자동으로 하지 않습니다 — 항상 사람이 확정.
단계 카드 ①~⑤각 단계를 개별 실행할 수도 있습니다. 순서를 건너뛰면 "③을 먼저 실행하세요"라고 로그에 안내. 상태 배지: 대기 진행중 완료 실패
[다운로드 생략] 체크폴더에 풀어둔 GeoLite2-Country-Blocks-IPv4.csv / Locations-en.csv 를 사용. zip을 수동으로 받았거나 재시도할 때 유용.
⑤ [스위치] 버튼④ 통과 시에만 활성화. 확인창을 거쳐 CREATE OR REPLACE SYNONYM 실행 (원자적·무중단). 전환 직후 건수와 IS_KOREA_IP 샘플 판정을 자동 확인.
[롤백] 버튼이번 세션에 스위치한 경우에만 활성화. 이전 테이블로 즉시 원복 (역시 무중단).
LIVE LOG실시간 진행 로그. 게이트 통과는 초록, 실패는 빨강. 적재 중에는 2만 건 단위 진행률 표시. [지우기]는 화면만 지우고 파일 로그는 유지.
요약줄활성/대기 테이블, 기존→신규 건수, 스위치 완료 여부를 한 줄로 표시.

6 · 게이트 5개 — 전부 통과해야 스위치

게이트단계검사 내용실패하면
G1② 변환변환 건수 ≥ 300,000 (min_rows 설정값)다운로드 파일 불완전 의심 — 재다운로드
G2② 변환적재 전 CSV 자체에서 샘플 판정: 223.62.180.1=KR / 8.8.8.8=US데이터 자체 이상 — DB에 넣기 전에 차단됨
G3③ 적재DB 적재 건수 == CSV 건수적재 유실 — 재실행
G4④ 검증신규 건수 ≥ 기존 활성 테이블 × 0.9급감 = 데이터 이상 — 스위치 차단
G5④ 검증통계수집 후 대기 테이블을 직접 조회해 샘플 판정 + 응답속도 < 0.5s판정 오류 또는 통계 누락(조회 수 초 이슈) — 스위치 차단
G5가 스위치 직전의 실전 리허설입니다 — 새 테이블이 실제 판정 쿼리로 올바른 국가를, 빠르게 돌려주는지 확인한 뒤에만 전환합니다. 가이드에 기록된 "통계 누락으로 조회가 수 초 걸린 이슈"가 여기서 자동으로 잡힙니다.

7 · 문제 해결

증상조치
bat 더블클릭 시 한글이 깨지고 "내부 또는 외부 명령…이 아닙니다" 연발구버전 bat(UTF-8 저장본)의 인코딩 문제. CP949로 저장된 최신 bat로 교체하면 해결.
ModuleNotFoundError: oracledb (③에서 실패)pip install oracledb 후 ③부터 다시 실행. 앞 단계 결과는 유지됩니다.
"geoip_config.json 이 없습니다"3-2 참고해 같은 폴더에 설정 파일 생성.
① 다운로드 실패 HTTP 401라이선스 키 오류 — MaxMind 계정에서 키 재발급. 급하면 브라우저로 zip 수동 다운로드 → 압축 해제 → [다운로드 생략] 체크 후 진행.
G5 실패 — 조회 0.5s 초과통계수집이 안 먹었거나 인덱스 문제. ④를 한 번 더 실행 (통계 재수집). 반복되면 SELECT index_name, status FROM user_indexes WHERE table_name LIKE 'TB_CM_GEOIP_RANGE_%' 확인.
스위치 후 판정이 이상함[롤백] 버튼 — 이전 테이블로 즉시 원복. 콘솔을 이미 껐다면 SQL로: CREATE OR REPLACE SYNONYM TB_CM_GEOIP_RANGE FOR 이전테이블;
브라우저가 안 열림 / 페이지 접속 안 됨검은 창(서버)이 살아있는지 확인 후 주소창에 http://127.0.0.1:8765 직접 입력. 8765 포트를 다른 프로그램이 쓰면 geoip_console.py 상단 PORT 변경.
다른 PC에서 접속하고 싶음보안상 의도적으로 막혀 있습니다 (127.0.0.1 전용). DB 계정 정보가 있는 콘솔이므로 본인 PC에서만 사용.
기억할 것 하나: ⑤ 스위치 전에는 무엇이 실패해도 서비스에 영향이 없습니다. 에러가 나면 당황하지 말고 로그 확인 → 해당 단계부터 재실행하면 됩니다.
