원래 테이블명 + _YYYYMMDD_001

이 패키지 하나만 설치하면 됩니다. 복사 순서 · 사전검증 · 백업 · 건수비교까지 전부 안에 들어 있어, 바깥에서 따로 챙길 스크립트가 없습니다. 기존 PKG_CM_COPY_GEN 과 PKG_MS_STORE_COPY 는 필요 없습니다.

01
감사컬럼 타입 자동 판별

REG_DT / MOD_DT 가 VARCHAR2 면 TO_CHAR(SYSDATE,'YYYYMMDDHH24MISS'), DATE 면 SYSDATE 를 씁니다. 이전 엔진은 무조건 SYSDATE 라 VARCHAR2(14) 컬럼에 '26/09/01' 같은 값이 조용히 들어갔습니다.

02
PK 없는 테이블 안전장치

PK가 없으면 중복차단 조건이 키 하나로만 만들어져, 대상에 행이 하나라도 있으면 전체가 걸러져 0건으로 끝납니다. 이제는 사유를 남기고 건너뜁니다.

02+
PK 말고 UNIQUE 도 봅니다

PK 없이 UNIQUE 인덱스만 있는 테이블, UNIQUE가 둘 이상 달린 테이블을 위해 PK → UNIQUE 제약 → UNIQUE 인덱스 순으로 찾습니다. 여러 개면 정해진 규칙으로 하나를 고르고 무엇을 골랐는지 매번 출력합니다. SP_KEY_SET 으로 직접 지정할 수도 있습니다.

03
교차복사 사전 검사

대상 PK 컬럼을 원본에서 못 끌어오면 실행 중 ORA-00904로 죽던 것을, 조립 전에 검사해 건너뜁니다.

04
오류를 삼키지 않음

백트레이스를 남기고 기본값으로 즉시 중단합니다. 기존 두 패키지 모두 WHEN OTHERS로 오류를 뭉갰고, PKG_MS_STORE_COPY 는 RAISE_APPLICATION_ERROR 다음 줄에 ROLLBACK 을 둬서 그 줄이 실행되지 않았습니다.

05
트랜잭션은 호출자가 결정

프로시저 안에서 COMMIT / ROLLBACK 하지 않습니다. 나눠담기 모드만 예외입니다.

06
세 가지 모드

S 신규만 · M 있으면 갱신(MERGE) · R 지우고 다시 넣기. 기존 매장복사 패키지의 DELETE 후 INSERT 방식이 R에 해당합니다.

07
컬럼 별칭과 값 지정

MS_BRAND_CD 는 HQ_BRAND_CD 에서 자동으로 끌어옵니다. SP_MAP_ADD 로 특정 컬럼 값을 직접 지정할 수 있습니다.

08
나눠담기

묶음 단위로 넣고 커밋해 UNDO와 락을 오래 잡지 않습니다. 0건이 될 때까지 스스로 반복합니다.

09
세 방향이 한 줄

SP_HQ2HQ · SP_HQ2MS · SP_MS2MS 가 복사 순서와 사전검증을 들고 있습니다. 본사·매장 소속 검증, 상품 필터, 확정 여부까지 안에서 처리합니다. 일부만 하고 싶으면 테이블 목록을 넘기면 됩니다.

10
POS 번호 매핑

POS_ENVST · POS_FNKEY · POS_TERMNL · POS_CONFG_XML 은 대상 매장의 POS 번호에 맞춰 옮깁니다. 원본에 POS가 없으면 아무것도 하지 않습니다. 기존 구현이 대상 설정만 지우던 자리입니다.

11
부속까지 포함

SP_CHECK_ENV 환경점검, SP_BACKUP 백업, SP_VERIFY 건수비교, SP_NMCODE_STORE 매장 공통코드, SP_DIFF 컬럼비교.

패키지 밖에서 챙길 것은 이것뿐입니다
  • 소유자 계정으로 돌리거나, 롤이 아닌 직접 권한을 받은 계정일 것. 아니면 딕셔너리가 안 보여 전부 "테이블 없음"으로 조용히 건너뜁니다.
  • 대상 뿌리 행이 미리 있을 것. 본사는 TB_HQ_OFFICE, 매장은 TB_MS_STORE.
  • 터치키 화면 구성 XML 은 POS 번호가 얽혀 있어 여전히 개별 확인이 필요합니다.
아래 환경 점검 카드가 위 항목을 한 번에 검사합니다.

값을 어떻게 정하는가

컬럼 목록을 스크립트가 들고 있지 않습니다. 실행할 때마다 딕셔너리에서 대상 테이블의 컬럼을 읽어 문장을 조립합니다. 컬럼이 추가돼도 손댈 곳이 없습니다. 컬럼 하나의 값은 아래 순서로 정하고, 먼저 걸리는 것이 이깁니다.

순서값
1. SP_MAP_ADD이번 건에만 직접 지정한 값
2. 키 컬럼대상 키값 리터럴 (H0514 · S611429 등)
3. REG_DT / MOD_DT컬럼 타입을 보고 TO_CHAR(SYSDATE,'YYYYMMDDHH24MISS') 또는 SYSDATE
4. REG_ID / MOD_IDG_USER_ID 값
5. 같은 이름원본의 같은 컬럼
6. 별칭등록된 다른 이름. 기본으로 MS_BRAND_CD ← HQ_BRAND_CD
7. 없음NULL. NOT NULL 컬럼이면 경고를 찍습니다

중복 판단 키를 어떻게 찾는가

PK만 보지 않습니다. PK가 없고 UNIQUE 인덱스만 있는 테이블, UNIQUE가 여러 개 달린 테이블이 실제로 있기 때문입니다. 아래 순서로 찾습니다.

  1. SP_KEY_SET 으로 직접 지정한 컬럼
  2. 기본키(PK)
  3. UNIQUE 제약
  4. UNIQUE 인덱스 — 제약이 안 걸린 것만

3번과 4번은 여러 개일 수 있습니다. 그럴 때는 복사 키 컬럼을 포함한 것 → 컬럼 수가 적은 것 → 이름 순으로 하나를 고르고, 무엇을 골랐는지와 후보가 몇 개였는지를 매번 출력합니다. 함수기반 인덱스의 숨은 컬럼(SYS_NC…)이 낀 것은 후보에서 뺍니다.

키에 NULL을 허용하는 컬럼이 끼면 그 값이 NULL인 행은 중복 차단이 새어나갑니다. 이 경우에도 경고를 찍습니다.

모드동작
S 신규만대상에 없는 행만 넣습니다. 기존 값은 손대지 않습니다. 키가 없으면 건너뜁니다.
M 갱신키가 같으면 UPDATE, 없으면 INSERT. REG_DT · REG_ID 는 갱신하지 않아 등록 이력이 남습니다.

복사할 테이블

본사 기준정보를 대상 매장으로 내립니다. 신규 매장 개설 세팅이나 기존 매장 재적용에 씁니다. 원본은 TB_HQ_*, 대상은 TB_MS_* 라 컬럼이 서로 다릅니다. 엔진은 대상 컬럼을 기준으로 조립하고, 원본에 없는 컬럼은 NULL로 둡니다.

세 방향 중 가장 위험합니다 원본 TB_HQ_* 와 대상 TB_MS_* 는 컬럼 구성이 다릅니다. 엔진은 대상 컬럼 기준으로 조립하고 원본에 없는 컬럼은 NULL로 둡니다.
  • 실행 전에 컬럼 비교 카드를 먼저 돌려 NOT NULL, 기본값 없음 이 찍히는 컬럼을 확인하세요.
  • TB_MS_STORE_NMCODE 는 USE_TARGET_FG 규칙이 본사와 달라 개별 매핑을 씁니다.
  • 터치키 화면 구성은 테이블이 아니라 XML에 있습니다.

복사할 테이블

원본 매장의 기준정보와 환경을 대상 매장으로 복사합니다. 두 매장은 같은 본사 소속이어야 하고, 엔진이 이를 검사한 뒤 아니면 멈춥니다. POS 번호가 들어가는 표는 대상 매장의 POS 구성에 맞춰 번호를 바꿔 옮깁니다.

기존 PKG_MS_STORE_COPY 에서 확인된 문제 같은 일을 하는 기존 패키지가 있습니다. 그대로 쓰려면 아래를 먼저 고치세요.
  • 원본 매장에 POS가 없으면 SP_MS_POS_ENVST / SP_MS_POS_FNKEY 가 대상 설정을 지우고 아무것도 넣지 않습니다. DELETE가 IF 밖에 있습니다.
  • 환경값 4021을 원본 POS 번호로 판단합니다. 원본 1대 · 대상 3대면 세 대 모두 메인으로 잡힙니다.
  • SP_MS_STORE_NNCODE 가 PARENT_CD 자리에 NMCODE_GRP_CD 를 넣습니다.
  • 다중사업자 분기의 VAN 정보가 'KCP' / '1234567890' 으로 하드코딩돼 있습니다.
  • 매장 복사인데 본사 테이블 TB_HQ_PRODUCT_STORE / TB_HQ_COUPON_STORE 를 건드립니다.

복사할 테이블

복사 대상 후보와 추정 키입니다. 회색으로 지워진 줄은 의도적으로 복사하지 않는 테이블입니다.
