01이런 도구입니다

화면 빌더는 코드를 몰라도 홈페이지·랜딩·대시보드 같은 화면을 조립할 수 있는 단일 HTML 파일 도구입니다. 파일을 브라우저로 여는 것만으로 바로 동작하며, 서버·설치·로그인이 전혀 필요 없습니다. 기획자가 "이런 화면이 필요하다"는 것을 말과 그림 대신 실제로 클릭해 볼 수 있는 화면으로 만들어 전달하는 것이 목적입니다.

결과물은 두 가지입니다

  • 🌐 HTML 내보내기 — 만든 화면 그대로 열리는 독립 HTML. 한 파일로 받거나 페이지별 파일로 나눠 받을 수 있고(11장), 두 방식 모두 페이지 이동(메뉴·버튼·사이드메뉴 클릭)이 실제로 동작합니다. 설계 검토용은 물론, 안내 페이지·사내 공지처럼 "보여주는 화면"이라면 간단한 실사용 페이지로도 쓸 수 있습니다.
  • 📑 화면정의서 — 페이지 구조·행/열 구성·블록 목록·주석·화면 문구를 표로 정리한 인쇄용 문서. 개발팀에 전달하는 설계서가 됩니다(12장).

전체 작업 흐름

그림 1. 기본 작업 흐름 — 템플릿에서 시작해 내용을 바꾸고, 두 가지 결과물로 내보냅니다.
Note
작업 내용은 브라우저에 자동 저장되어 탭을 닫아도 이어서 작업할 수 있고(10장), 별도로 JSON 저장 파일로 내려받아 다른 PC로 옮기거나 백업할 수 있습니다. 도구 HTML 파일 자체에는 작업 내용이 저장되지 않는다는 점만 기억하세요.

02화면 구성과 두 가지 모드

화면은 크게 상단 도구막대와 캔버스 두 영역입니다. 캔버스는 완성될 화면의 실제 모습 그대로이며, 그 위에서 직접 클릭해 편집합니다.

그림 2. 편집 화면 구성 — 상단 도구막대, 캔버스, 그리고 블록을 선택했을 때 나타나는 도구들.

캔버스에서의 기본 조작

  • 텍스트 입력 — 제목·본문·표 셀·카드 문구 등 거의 모든 글자는 화면에서 직접 클릭해 입력합니다. 입력을 마치면 바깥의 빈 곳을 한 번 클릭해야 반영됩니다(반영 전에 페이지를 전환하면 그 글만 유실될 수 있음).
  • 블록 선택 — 블록을 클릭하면 파란 테두리로 선택되고, 우상단에 블록 도구(속성 · ▲▼ 이동 · ⧉ 복제 · ✕ 삭제)가 나타납니다. 동시에 도구막대의 파란 영역에 그 블록의 속성(크기·색·열 수 등)이 표시됩니다.
  • 드래그 손잡이 — 블록에 마우스만 올려도 좌상단에 ⠿ 손잡이가 나타나 바로 끌어 옮길 수 있습니다(5-1장).

03가장 빠른 시작 — 예시 템플릿 60종

빈 화면에서 시작하는 것보다 비슷한 유형의 템플릿을 골라 내용만 바꾸는 것이 압도적으로 빠릅니다. 도구막대의 📚 예시 템플릿 (60종)… 콤보에서 유형을 고르면 확인창이 뜬 뒤 화면 전체가 그 예시로 바뀝니다. 유명 홈페이지들의 대표 레이아웃을 본떠 만들었으므로, 구조는 그대로 두고 문구·데이터만 교체하면 됩니다.

따라 하기 — 템플릿으로 5분 만에 첫 화면 만들기

  1. 📚 예시 템플릿 콤보에서 목적에 가까운 유형을 선택합니다(예: 회사 소개면 ③, 관리 화면이면 ㉙).
  2. 확인창에서 적용을 누릅니다. 기존 작업이 있었다면 Ctrl+Z로 언제든 되돌릴 수 있습니다.
  3. 화면의 제목·본문을 클릭해 우리 내용으로 바꿉니다. 입력 후 바깥을 클릭해 반영합니다.
  4. 필요 없는 블록은 클릭 → 우상단 ✕로 지우고, 필요한 블록은 열 하단 ＋ 블록 추가…로 더합니다.
  5. 👁 미리보기로 완성 모습과 페이지 이동을 확인합니다.

04페이지 — 추가·이동·링크 연결

하나의 작업은 여러 페이지로 구성할 수 있습니다(홈 · 소개 · 문의 …). 도구막대 맨 앞 [페이지] 섹션의 콤보로 페이지를 전환하고, ＋ 페이지 ✎ 이름 ⧉ 복제 ✕ 삭제로 관리합니다. 메뉴바·푸터는 모든 페이지에 공통으로 표시되고, 행·블록·주석·화면 문구는 페이지별로 따로 저장됩니다.

페이지 순서와 하위(Tree) 구조 010

  • ◀ 순서 / 순서 ▶ — 현재 페이지를 목록에서 앞/뒤로 옮깁니다. 페이지 콤보의 순서, 페이지별 내보내기의 파일 번호(01_, 02_…), 화면정의서의 페이지 순서에 모두 반영됩니다.
  • ⇥ 하위 — 현재 페이지를 하위 페이지로 지정/해제합니다. 페이지 콤보에 └ 들여쓰기로 표시되고 화면정의서에도 반영되어, 페이지가 많을 때 상위-하위 Tree로 정리할 수 있습니다.
  • 하위 지정은 정리·문서화용 표시입니다. 화면에서의 이동 경로가 자동으로 바뀌지는 않습니다 — 링크 연결은 여전히 아래의 "이름 맞추기" 규칙을 따르며, 상위 메뉴 밑으로 묶어 이동시키려면 8장의 드롭다운 메뉴를 함께 사용하세요.

링크는 "이름 맞추기"로 연결됩니다

이 도구의 페이지 연결 방식은 단 하나의 규칙입니다 — 항목의 이름이 페이지명과 정확히 같으면(공백 포함) 자동 연결. 별도의 링크 설정 화면이 없습니다.

그림 3. 링크 연결 규칙 — 메뉴바·사이드메뉴·버튼의 이름이 페이지명과 같으면 자동 연결됩니다. 연결된 항목에는 편집 모드에서 ↗ 표시가 붙습니다.
  • 연결 여부 확인 — 편집 모드에서 연결된 메뉴·사이드메뉴 항목에는 작은 ↗ 표시가 붙습니다. ↗이 없으면 이름이 다른 것이니 철자·공백을 확인하세요.
  • 버튼의 직접 지정 — 버튼은 표시 문구와 이동 대상이 다를 수 있으므로 이름=색>페이지명 형식을 지원합니다. 예: 홈으로=회색>홈, 지금 신청=파랑>신청. >페이지명을 생략하면 문구 자체가 페이지명과 같을 때만 연결됩니다.
  • 이동이 동작하는 곳 — 미리보기와 내보낸 HTML. 편집 모드에서는 클릭이 편집으로 쓰이므로 이동하지 않습니다.
  • 페이지 이름을 바꾸면 기존 메뉴·버튼과의 이름이 어긋나 연결이 끊깁니다. 이름 변경 후에는 메뉴·버튼 문구도 함께 맞춰 주세요.

05행(섹션)과 열 — 레이아웃 15종

화면의 뼈대는 행(가로 섹션)입니다. 행을 위에서 아래로 쌓아 페이지를 만들고, 각 행은 1~6개의 열로 나뉘며, 열 안에 블록이 들어갑니다.

그림 4. 행·열 구조 — 행을 쌓고, 행 안을 열로 나누고, 열 안에 블록을 넣습니다.

행 추가와 관리

  1. 도구막대의 열 분할 콤보에서 원하는 레이아웃(예: 2열 25:75)을 고릅니다.
  2. ＋ 행 추가를 누르면 현재 페이지 맨 아래에 새 행이 생깁니다.
  3. 행에 마우스를 올리면 우상단에 행 도구가 나타납니다 — ⠿ 손잡이(드래그 이동) · 배경(밴드) 색 · 레이아웃 변경 · ▲▼ 이동 · ⧉ 복제 · ✕ 삭제.
  4. 각 열 하단의 ＋ 제목 ＋ 본문 ＋ 카드 또는 ＋ 블록 추가…로 블록을 채웁니다.

05-1블록·행 옮기기 — 드래그&드롭 최신 추가

블록과 행은 ⠿ 손잡이를 잡고 끌어서 옮깁니다. 손잡이는 마우스를 올렸을 때만 나타나므로 평소에는 화면을 가리지 않고, 손잡이를 잡았을 때만 드래그가 시작되므로 글자 편집이나 블록 선택과 부딪히지 않습니다.

대상손잡이 위치옮길 수 있는 범위
블록블록에 마우스를 올리면 좌상단같은 열 안의 순서 변경 + 다른 열 · 다른 행으로 이동
행(섹션)행 도구막대 맨 앞페이지 안에서 위아래 순서 변경
그림 5. 드래그 중 화면 표시 — 반투명 사본이 커서를 따라오고, 받는 열은 파란 테두리, 놓일 자리는 파란 가로선으로 표시됩니다.

끄는 동안 보이는 표시

  • 반투명 사본이 커서를 따라옵니다 — 지금 무엇을 옮기는 중인지 알려줍니다.
  • 파란 가로선이 놓일 자리를 정확히 가리킵니다. 블록은 이 선이 걸린 위·아래 사이로 들어갑니다.
  • 받는 열은 파란 테두리로 강조되고, 원래 자리의 블록은 흐려집니다.
  • 빈 열 위로 가져가도 선이 표시되며, 그대로 놓으면 그 열의 첫 블록이 됩니다.

알아두면 편한 동작

  • 자동 스크롤 — 화면 위아래 가장자리로 끌면 페이지가 저절로 스크롤됩니다. 긴 화면에서 멀리 떨어진 곳으로 옮길 때 쓰세요. 상단 도구막대에 가려진 구간도 이때 드러납니다.
  • 취소 — 끌던 도중 Esc를 누르거나 캔버스 바깥에 놓으면 아무 일도 일어나지 않습니다.
  • 되돌리기 — 이미 놓았더라도 Ctrl+Z로 되돌아갑니다. 제자리에 그대로 놓으면 실행취소 기록도 남지 않습니다.
  • 마우스뿐 아니라 터치·펜으로도 같게 동작합니다.
Note
기존 ▲▼ 버튼은 그대로 있습니다. 한 칸씩 정확히 옮길 때는 버튼이, 멀리 또는 다른 열로 옮길 때는 드래그가 편합니다. 열을 넘나드는 이동은 드래그로만 가능합니다.
Tip
⠿ 손잡이가 보이지 않는다면 미리보기 모드이거나 주석(📌)·텍스트(📝) 모드가 켜져 있는 경우입니다. 이 모드에서는 화면 클릭이 핀·문구 추가로 쓰이기 때문에 드래그가 꺼집니다. 편집 모드로 돌아오면 다시 나타납니다.

06-1새 블록 3종 자세히 — 슬라이드 · 팝업 · HTML 010

슬라이드(캐러셀)

여러 장의 배너를 한 자리에서 넘겨 보여주는 블록입니다. 그룹 홈페이지에서 추가합니다. 쇼핑몰·포털 홈 상단의 회전 배너를 표현할 때 씁니다.

  1. 블록을 추가하면 슬라이드 2장이 기본으로 들어 있습니다.
  2. ‹ › 화살표나 아래 점(인디케이터)을 눌러 편집할 슬라이드로 이동합니다.
  3. 제목·설명을 화면에서 직접 클릭해 입력합니다.
  4. 우상단 도구에서 ＋슬라이드/－슬라이드로 장수를 조절하고, 속성에서 배경 톤(어두운/파랑/밝은) · 자동넘김/수동 · 현재 슬라이드의 배경 이미지 URL(비우면 색 배경)을 지정합니다.
  • 미리보기·내보낸 HTML에서는 화살표·점 클릭이 실제로 동작합니다.
  • 자동넘김을 켜면 내보낸 HTML에서 5초마다 다음 장으로 넘어가고, 마우스를 올린 동안은 정지합니다. 편집·미리보기에서는 자동으로 넘어가지 않습니다(편집 방해 방지).

팝업(모달)

  • 편집 화면에서는 내용이 가려지지 않도록 보라 점선 카드로 표시되며, 제목·내용을 직접 입력합니다.
  • 속성에서 표시 위치(중앙 모달 / 우하단 카드)와 닫기 버튼 문구를 지정합니다.
  • 미리보기·내보낸 HTML에서는 팝업 블록이 놓인 페이지에 들어올 때 떠 있는 창으로 표시되고, ✕나 닫기 버튼으로 닫힙니다. "오늘 하루 보지 않기" 문구는 설계 표시용(모양만)입니다.
  • 팝업 블록은 페이지당 1개를 권장합니다. 여러 개 두면 겹쳐서 표시됩니다.
그림 6. 팝업 블록 — 편집 중에는 점선 카드, 미리보기·내보낸 HTML에서는 실제 팝업으로 뜹니다.

HTML 코드

임의의 HTML을 그대로 렌더링하는 블록입니다. 그룹 기본에서 추가합니다. "자리" 블록(동영상 자리·지도 자리)이 모양만 잡는 것과 달리, HTML 블록은 실제로 동작하는 embed를 넣는 용도입니다.

  1. 블록을 추가한 뒤, 우상단 도구의 〈/〉 코드 버튼으로 코드 편집창을 엽니다.
  2. 유튜브 — 영상 페이지의 [공유 → 퍼가기]에서 복사한 <iframe …> 코드를 붙여넣습니다.
  3. 지도 — 구글지도·네이버지도의 embed(퍼가기) 코드도 같은 방식입니다.
  4. 저장하면 캔버스에 실제 embed가 표시됩니다. 재생·조작 확인은 미리보기나 내보낸 HTML에서 합니다.
주의
안전을 위해 편집 화면에서는 script가 실행되지 않고, 코드 영역 클릭은 블록 선택으로 쓰입니다(iframe 조작 불가). 내보낸 HTML에서는 붙여넣은 코드가 그대로 실행되므로, 출처를 신뢰할 수 있는 코드만 사용하세요.

07데이터 블록 — 표·요약카드·그래프

대시보드·보고 화면의 핵심은 데이터 3종 블록입니다. 특히 표 → 그래프 연동은 이 도구의 가장 강력한 기능 중 하나로, 표의 값을 고치면 그래프가 즉시 다시 그려집니다.

그림 7. 표 → 그래프 연동 — 표가 원본, 그래프는 그 표를 바라보는 뷰입니다.

따라 하기 — 표에서 그래프 만들기

  1. 표 블록을 먼저 만들고 데이터를 입력합니다. 첫 컬럼이 라벨(예: 월), 숫자가 많은 컬럼이 값 시리즈로 자동 인식됩니다.
  2. 같은 페이지에 그래프 블록을 추가합니다.
  3. 그래프 블록을 클릭 → 속성에서 원본 표(같은 페이지의 표 목록에서 선택)와 유형 · 높이를 고릅니다.
  4. 이후 표 값을 고치면 그래프가 즉시 다시 그려집니다. 컬럼명을 바꾸면 범례에도 반영됩니다.

  • 내보낸 HTML에는 그래프가 정적 SVG로 담겨, 인터넷이 없는 환경에서도 그대로 보입니다.
  • 표에 숫자 컬럼이 하나도 없으면 그래프를 그릴 수 없습니다("표를 선택하세요" 안내가 유지됨).

08메뉴바(GNB)와 푸터

메뉴바와 푸터는 모든 페이지 공통 영역입니다. 도구막대의 메뉴바/푸터 체크박스로 켜고 끕니다.

메뉴바 편집 — 미니 도구

편집 모드에서 메뉴바에 마우스를 올리면 미니 도구가 나타나 다음을 지정할 수 있습니다.

메뉴 항목쉼표 입력드롭다운은 괄호, 풀폭 메뉴는 대괄호 문법(아래 참고)

푸터의 두 줄(회사 문구·연락처)은 화면에서 직접 클릭해 수정합니다.

하위(드롭다운) 메뉴 010

  • 메뉴 입력칸에서 괄호와 /로 하위 메뉴를 지정합니다 — 예: 홈, 회사(소개/문의), 고객센터 → "회사"에 마우스를 올리면 소개·문의 드롭다운이 펼쳐집니다.
  • 하위 항목도 상위와 똑같이 이름이 페이지명과 같으면 자동 연결됩니다(편집 모드에서 ↗ 표시). 상위 항목은 자체 페이지 없이 묶음 제목으로만 써도 됩니다.
  • 드롭다운은 편집 캔버스·미리보기·내보낸 HTML(한 파일/페이지별) 모두에서 hover로 동작합니다.

좌우 풀폭(메가) 메뉴 010

  • 하위 메뉴를 작은 드롭다운 대신 화면 좌우로 꽉 차는 풀폭 패널로 펼치고 싶으면 괄호 대신 대괄호 [ ]를 씁니다 — 예: 제품·솔루션[링크포스:올인원 POS/키오스크:셀프 주문·결제/포스 하드웨어:단말기·주변기기]
  • 각 하위 항목은 이름:설명 형식으로, 패널에 굵은 제목 + 회색 설명으로 나란히 배치됩니다. 설명(:설명)은 생략할 수 있습니다.
  • 하위 항목의 이름이 페이지명과 같으면 자동 연결됩니다(설명은 표시용). 상위에 마우스를 올리면 메뉴바 바로 아래에 흰색 풀폭 패널이 펼쳐지며, 편집·미리보기·양쪽 내보내기 모두에서 동작합니다.
  • 한 메뉴바에서 일반 드롭다운(괄호)과 풀폭 메뉴(대괄호)를 섞어 쓸 수 있습니다.
그림 8. 드롭다운(괄호) vs 풀폭 메가 메뉴(대괄호) — 하위 항목 이름이 페이지명과 같으면 자동 연결(↗)됩니다.
Tip — 어느 쪽을 쓸까
하위 항목이 2~3개면 드롭다운(괄호), 항목마다 설명을 붙여 소개하고 싶거나 항목이 많으면 풀폭(대괄호)이 어울립니다. ㉘ 인트라넷 포털에 드롭다운의 기본 예("회사" 메뉴)가, ㉛~㊺ (2단)·46~60 (2단_좌우) 템플릿 30종에 완성 견본이 있습니다(3장).

09주석(📌)과 텍스트 모드(📝) — 설계 의도 남기기

화면 모양만으로는 전달되지 않는 동작 스펙과 화면 규칙을 남기는 두 가지 모드입니다. 둘 다 페이지별로 따로 저장되고, 내보낸 HTML과 화면정의서에 포함됩니다.

그림 9. 📌 번호 핀(지점별 동작 스펙)과 📝 화면 문구(상시 표시 규칙) — 내보낸 HTML·화면정의서에 모두 포함됩니다.

주석 모드 (📌) — 번호 핀 + 설명 목록

  1. 📌 주석 모드를 켭니다(버튼이 "켜짐" 상태로 바뀜).
  2. 화면에서 설명이 필요한 지점을 클릭하면 빨간 번호 핀이 찍힙니다.
  3. 캔버스 아래 목록에서 각 번호의 설명을 입력합니다 — "이 버튼을 누르면 어떤 API를 호출" 같은 지점별 동작 스펙.
  4. 핀을 다시 클릭하면 삭제됩니다. 다 달았으면 모드를 꺼서 편집으로 돌아옵니다.

텍스트 모드 (📝) — 화면 위에 문구 직접 표시

  1. 📝 텍스트 모드를 켜고 화면을 클릭하면 그 자리에 문구 입력창이 열립니다.
  2. 편집 창에서 글자 색 5종(빨강·파랑·초록·회색·검정) · 크기(12~20px) · 형광펜 배경을 지정합니다.
  3. 문구를 드래그해 위치를 옮기고, 클릭하면 다시 편집합니다. 내용을 비우고 저장하면 자동 삭제됩니다.
  • "※ 마감 후에는 수정 불가" 같이 화면에 상시 보여야 할 규칙·주의 문구를 위치 그대로 전달하는 용도입니다.
  • 주석 모드와 텍스트 모드는 동시에 켤 수 없습니다 — 한쪽을 켜면 다른 쪽이 자동으로 꺼집니다.
Note — 둘의 역할 구분
📌 주석은 "이 지점이 어떻게 동작해야 하는가"(개발 스펙, 번호로 참조), 📝 텍스트는 "화면에 이 문구가 이 위치에 보여야 한다"(화면 자체의 요구사항)입니다. 핀·설명 목록·텍스트 문구는 모두 내보낸 HTML(한 파일·페이지별)과 화면정의서에 포함되며, 화면정의서에는 "📌 주석"과 "📝 화면 문구"가 각각 별도의 표로 정리됩니다.

10저장 · 자동 저장 · 실행취소

자동 저장 — 닫아도 이어서 작업 최신 추가

편집을 멈추면 1초 안에 현재 작업 전체(페이지·블록·메뉴바·푸터·주석·텍스트 문구)가 브라우저에 보관됩니다. 탭을 실수로 닫거나 새로고침해도 다음에 열 때 그대로 이어서 작업할 수 있습니다.

  • 도구막대 오른쪽에 자동 저장됨 · 14:32 처럼 마지막 보관 시각이 표시됩니다.
  • 다시 열면 이전 내용이 자동으로 복구되고, 화면 위에 노란 알림줄이 뜹니다 — 이전에 작업하던 내용을 불러왔습니다.
  • 처음부터 새로 시작하려면 그 알림줄의 기본 예시로 새로 시작을 누릅니다(확인창이 뜨고, 보관된 이전 내용도 함께 지워집니다). 알림줄만 치우려면 ✕.
  • 드래그로 옮긴 순서, 화면에서 직접 입력한 글자도 모두 함께 보관됩니다.
주의 — 자동 저장의 한계
자동 저장은 이 컴퓨터의 이 브라우저 안에서만 유효합니다. 다른 PC·다른 브라우저로 옮기거나 백업·공유하려면 💾 저장(JSON)을 쓰세요. 사생활 보호(시크릿) 모드처럼 보관이 막힌 환경에서는 자동 저장이 꺼지고, 도구막대에 빨간 글씨로 그 사실이 표시됩니다 — 그때는 JSON 저장으로 직접 보관하세요. 또한 브라우저의 "인터넷 사용 기록 삭제"로 사이트 데이터를 지우면 자동 저장분도 함께 사라집니다.

저장(JSON)·불러오기

  • 💾 저장 — 전체 작업을 page_builder_날짜.json으로 내려받습니다. 다른 사람에게 넘기거나 다른 PC에서 이어서 작업할 때, 그리고 중요한 시점을 따로 보관할 때 씁니다.
  • 📂 불러오기 — 저장한 JSON을 다시 엽니다. 이전 버전(001~009)에서 저장한 파일도 자동 변환되어 열립니다.

실행취소·초기화

  • ↶ 실행취소 / ↷ 다시실행 — 최대 60단계. 단축키 Ctrl+Z / Ctrl+Y. 텍스트 수정은 물론 템플릿 적용·페이지 삭제·드래그 이동도 되돌릴 수 있습니다.
  • 🗑 초기화 — 모든 페이지를 지우고 빈 화면으로 시작합니다(확인창 후 실행).
Tip — 두 저장의 역할
자동 저장은 "실수로 닫아도 잃지 않게" 하는 안전망이고, JSON 저장은 "옮기고 나누고 되돌아갈 수 있는" 보관본입니다. 하루 작업을 마칠 때, 템플릿을 갈아엎기 전, 큰 구조 변경 전에는 JSON을 한 번 받아 두세요.

11HTML 내보내기 — 한 파일 / 페이지별

두 방식 모두 편집 흔적(점선·버튼·입력 표시) 없이 완성된 화면만 담기고, 주석 핀·설명 목록·텍스트 문구도 포함됩니다. 좁은 화면(모바일)에서는 열이 자동으로 세로로 쌓입니다.

Note — 내보낸 HTML에서 실제로 동작하는 것 010
페이지 이동(메뉴·버튼·사이드메뉴)에 더해 드롭다운·메가 메뉴 펼침, 슬라이드 넘김·자동재생, 팝업 표시·닫기, HTML 블록의 embed(유튜브·지도 등)가 내보낸 파일에서 그대로 동작합니다. 반면 검색창·입력 폼·로그인 박스는 모양만 있는 설계용입니다(FAQ 참고).
그림 10. 한 파일(파일 안 전환) vs 페이지별(파일 간 실제 링크) — 페이지별은 같은 폴더에 두어야 이동이 동작합니다.

🌐 HTML (한 파일)

  • 모든 페이지가 파일 하나에 담깁니다. 메뉴·버튼·사이드메뉴를 클릭하면 파일 안에서 페이지가 전환됩니다.
  • 파일 한 개만 보내면 되므로 메신저·메일 공유에 편리합니다.

🗂 HTML (페이지별)

  • 페이지마다 파일이 따로 내려갑니다. 파일명은 순번+페이지명 — 예: 01_홈.html, 02_신청.html (폴더에서 페이지 순서대로 정렬됨. 순번은 4장의 페이지 순서를 따름).
  • 메뉴·버튼·사이드메뉴의 페이지 연결이 파일 간 실제 링크로 변환되어, 01_홈.html에서 "신청"을 누르면 02_신청.html로 이동합니다. 각 파일의 메뉴바에는 현재 페이지에 밑줄이 표시됩니다.
  • 여러 파일이 순차로 내려가므로 브라우저가 "여러 파일 다운로드 허용"을 물으면 허용해 주세요.
  • 파일들을 같은 폴더에 두어야 페이지 간 이동이 동작합니다. 파일 이름을 바꾸면 링크가 끊깁니다. 개발자에게 전달할 때는 폴더째 압축해서 보내세요.
Tip — 어느 방식을 쓸까
페이지별 개발 담당자가 다르거나 화면 단위로 리뷰·이슈를 관리한다면 페이지별이, 빠른 전체 공유·모바일에서 열어보기에는 한 파일이 편합니다. 둘 다 받아서 용도에 맞게 쓰는 것도 방법입니다.

12화면정의서 출력

📑 화면정의서를 누르면 spec_날짜.html 문서가 내려받아집니다. 화면을 만들면서 자동으로 축적된 구조 정보를 표로 정리한 문서로, 별도로 다시 작성할 필요가 없습니다.

내보낸 HTML(화면 그대로) + 화면정의서(구조·스펙 표)를 한 벌로 전달하면, 개발자는 HTML로 화면을 눈으로 확인하고 정의서로 목록·스펙을 참조할 수 있어 별도 기획서 없이도 전달력이 높습니다. 📌 주석에 동작 스펙, 📝 문구에 화면 규칙까지 담아 두면 완성입니다.

13자주 묻는 질문(FAQ)

Q. 메뉴를 눌러도 페이지가 안 바뀌어요.

편집 모드에서는 클릭이 편집으로 쓰입니다. 미리보기로 전환하거나 내보낸 HTML에서 확인하세요. 그래도 안 되면 메뉴 항목명과 페이지명이 정확히 같은지(공백 포함) 확인하세요 — 연결된 항목에는 편집 모드에서 ↗ 표시가 붙습니다.

Q. 그래프가 "표를 선택하세요"라고만 나와요.

그래프는 같은 페이지의 표 블록을 원본으로 사용합니다. 표를 먼저 추가하고, 그래프 블록을 클릭 → 속성의 원본 콤보에서 표를 선택하세요. 표에 숫자 컬럼이 하나도 없으면 그릴 수 없습니다.

Q. 입력한 글이 사라졌어요.

텍스트는 입력 후 바깥을 클릭해야 반영됩니다. 반영되기 전에 페이지를 전환하면 그 글만 유실될 수 있으니, 입력을 마치면 빈 곳을 한 번 클릭하는 습관을 들이세요. 반영된 뒤에는 자동 저장이 받아 두므로 새로고침해도 남아 있습니다.

Q. ⠿ 손잡이가 안 보여서 블록을 끌 수 없어요.

세 가지를 확인하세요. ① 미리보기 모드가 아닌지(👁 버튼으로 편집 모드 복귀), ② 주석(📌)·텍스트(📝) 모드가 켜져 있지 않은지, ③ 블록 위에 마우스를 올렸는지. 손잡이는 마우스를 올린 블록의 좌상단, 행은 우상단 도구막대 맨 앞에 나타납니다.

Q. 블록을 끄는데 화면 맨 위에 놓을 수가 없어요.

화면 위쪽 가장자리로 계속 끌고 있으면 페이지가 자동으로 스크롤되면서 도구막대에 가려져 있던 자리가 드러납니다. 손을 떼지 말고 잠시 그대로 두세요.

Q. 새로 열었더니 지난번 작업이 그대로 떠 있어요.

자동 저장이 복구한 것으로, 정상 동작입니다. 처음부터 시작하려면 화면 위 노란 알림줄의 기본 예시로 새로 시작을 누르세요. 알림줄만 치우고 이어서 작업하려면 ✕를 누르면 됩니다.

Q. 회사 PC에서 하던 작업을 집에서 이어서 하려면?

자동 저장은 그 브라우저 안에만 남습니다. 💾 저장(JSON)으로 파일을 받아 옮긴 뒤, 다른 PC에서 📂 불러오기로 여세요. 도구 HTML 파일만 복사해서는 작업 내용이 따라가지 않습니다.

Q. 템플릿을 골랐는데 원래 작업이 지워졌어요.

Ctrl+Z(실행취소)로 되돌릴 수 있습니다. 템플릿 적용 전 확인창이 뜨므로, 작업 중에는 먼저 JSON 저장을 권장합니다.

Q. 페이지를 추가했는데 상단 메뉴바에 안 보여요.

메뉴바 항목은 자동으로 생기지 않습니다. 편집 모드에서 메뉴바에 마우스를 올리면 나타나는 메뉴 입력칸에 새 페이지 이름을 쉼표로 추가하세요. 페이지명과 정확히 같으면(공백 포함) 자동 연결되어 ↗ 표시가 붙습니다.

Q. 페이지별 내보내기를 받았는데 파일에서 메뉴를 눌러도 이동이 안 돼요.

페이지별 파일들은 같은 폴더 안에 함께 있어야 서로 이동합니다. 파일 하나만 옮겼거나 이름을 바꾸면 링크가 끊깁니다. 또한 브라우저가 "여러 파일 다운로드"를 차단해 일부 파일만 받아졌을 수 있으니, 내보내기 시 안내된 파일 개수와 실제 받은 개수를 확인하세요.

Q. 슬라이드가 편집 화면에서는 자동으로 안 넘어가요.

자동넘김은 내보낸 HTML에서만 동작합니다(편집·미리보기 중 화면이 저절로 바뀌면 편집을 방해하기 때문). 편집·미리보기에서는 ‹ › 화살표와 점으로 직접 넘겨 확인하세요.

Q. 팝업이 편집 화면에서는 카드로만 보여요.

의도된 동작입니다. 편집 중에는 내용이 가려지지 않도록 점선 카드로 표시되고, 미리보기나 내보낸 HTML에서 페이지에 들어올 때 실제 팝업으로 뜹니다.

Q. HTML 블록에 붙여넣은 유튜브가 편집 화면에서 클릭이 안 돼요.

편집 중에는 embed 영역 클릭이 블록 선택으로 쓰입니다(그래야 블록을 옮기고 지울 수 있습니다). 재생·조작은 미리보기나 내보낸 HTML에서 확인하세요.

Q. 실제 서비스로 그대로 써도 되나요?

내보낸 HTML은 정적 화면입니다. 검색창·입력 폼·로그인 박스는 모양만 있는 설계용이라 실제 동작하지 않습니다. 안내형 페이지·랜딩·사내 공지처럼 "보여주는 화면"은 그대로 사용 가능하고, 기능이 필요한 화면은 이 HTML을 개발 시안으로 전달하면 됩니다. 이때 📌 주석으로 동작 스펙을, 📝 텍스트 모드로 화면 규칙 문구를 함께 담아 보내면 별도 기획서 없이도 전달력이 높아집니다.
