국외 IP 로그인 차단 활성화 시 사용자 영향 정리

FN_CHK_LOGIN_BLOCK  C_BLOCK_MODE = 'N' → 'Y' 전환 기준  |  적용 지점 : 로그인 트리거(TR_TB_WB_LOGIN_HIST_R90) · 메뉴 이동(FN_GET_MENU_CHK_YN2)

1. 판정 흐름 (FN_CHK_LOGIN_BLOCK 공통)

순서 조건 결과
1 SMS 사용등록(TB_CM_SMS_USER_REGIST) 안 된 사용자 'Y' 허용 — 아무 영향 없음
2 SMS 등록자 + 한국 IP 'Y' 허용
3 SMS 등록자 + 해외 IP + TB_CM_IP_ALLOW 등재 (기간·USE_YN 유효) 'Y' 허용
4 SMS 등록자 + 해외 IP + 허용테이블 미등재 'N' 차단 + 이력 INSERT
5 SMS 등록자 + 사설 IP·GeoIP 매칭 실패(COUNTRY_CODE = NULL) + 허용테이블 미등재 'N' 차단 ← 주의

2. 차단 대상자가 실제로 겪는 것

① 로그인 시점 — 트리거 TR_TB_WB_LOGIN_HIST_R90

TB_WB_LOGIN_HIST INSERT 자체가 실패합니다. 트리거가 RAISE_APPLICATION_ERROR(-20001, ...)를 던지므로 애플리케이션(WAS)은 아래와 같은 오류를 받습니다.

ORA-20001: [TR_TB_WB_LOGIN_HIST_R90 : CHK]-[Login Blocked: Country Restriction,
momse08053,34.86.142.50,...,US,...,20260826143012]-...
사용자 화면에 보이는 메시지는 WAS 처리에 달려 있음 WAS가 이 ORA-20001 예외를 별도로 처리하지 않으면 "시스템 오류" 류의 일반 에러 페이지가 뜰 가능성이 높습니다. "로그인이 실패했습니다" 같은 정상 실패 메시지가 아닐 수 있으므로, 배포 전 테스트 계정으로 실제 화면을 확인하고 필요하면 "해외 IP 접속이 제한되었습니다. 관리자에게 문의하세요" 같은 안내 문구로 변환하는 처리를 WAS에 추가하는 것을 권장합니다.
로그인 이력 위치 변경
차단된 로그인 시도는 TB_WB_LOGIN_HIST에 남지 않습니다 (INSERT 롤백). 대신 TB_WB_LOGIN_HIST_BLOCK에 BLOCKED - ... 사유로 기록되므로, 차단 이후 추적·조회는 BLOCK 테이블에서 해야 합니다.

② 이미 로그인돼 있던 세션 — FN_GET_MENU_CHK_YN2

차단 활성화 시점에 이미 로그인해 있던 해외 접속자도 다음 메뉴 클릭부터 막힙니다. 함수가 'N'을 리턴하여 기존 메뉴 차단과 동일하게 "사용 불가" 처리됩니다. 이쪽은 기존 'N' 처리 UX가 이미 있으므로 별도 대응이 필요 없습니다.

3. 사용자 유형별 요약

사용자 로그인 메뉴 이동
SMS 미등록 사용자 (대다수) 정상 정상
SMS 등록 + 국내 접속 정상 정상
SMS 등록 + 해외 접속 + 허용 등록됨 (출장자 등) 정상 정상
SMS 등록 + 해외 접속 + 미등록 ORA-20001 로그인 실패 차단('N')
SMS 등록 + 사설 IP 유입 (맘스터치 등 내부망) 차단됨 — 주의 차단됨 — 주의

4. 켜기 전 반드시 확인할 것

  1. 사설 IP 오탐 — GeoIP에 매칭되지 않는 IP(사설망, 맘스터치 이슈)는 '한국 아님'으로 처리되어 차단됩니다. 관찰 기간 동안 TB_WB_LOGIN_HIST_BLOCK에서 COUNTRY_CODE IS NULL 건을 추출해, 정상 사용자는 TB_CM_IP_ALLOW에 등록하거나 사설 대역(10.x, 172.16~31.x, 192.168.x)을 IS_LOGIN_ALLOWED에서 예외 허용할지 정책을 결정해야 합니다.
  2. WAS의 ORA-20001 처리 — 차단 시 사용자에게 보이는 최종 메시지가 의도한 안내인지 테스트 계정으로 확인해야 합니다.

오탐 점검 쿼리 (관찰 기간 중 주기 실행)

SELECT  USER_ID
,       REAL_IP
,       COUNTRY_CODE
,       COUNT(*)            AS CNT
,       MIN(LOGIN_DATE)     AS FIRST_TRY
,       MAX(LOGIN_DATE)     AS LAST_TRY
FROM    TB_WB_LOGIN_HIST_BLOCK
GROUP
BY      USER_ID, REAL_IP, COUNTRY_CODE
ORDER
BY      CNT DESC
;

5. 차단 활성화 방법 (참고)

FN_CHK_LOGIN_BLOCK 함수의 아래 한 줄만 변경 후 함수만 재컴파일하면 로그인 트리거(R90)와 메뉴 이동(FN_GET_MENU_CHK_YN2)에 동시에 일괄 적용됩니다. 트리거 및 다른 호출처는 수정할 필요가 없습니다.

C_BLOCK_MODE    CONSTANT VARCHAR2(1) := 'N';   -- 관찰 모드 (현재)
C_BLOCK_MODE    CONSTANT VARCHAR2(1) := 'Y';   -- 차단 모드 (전환 시)
