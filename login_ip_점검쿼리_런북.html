SBPORA · LOGIN IP CONTROL

로그인 IP 점검 쿼리 런북

클라우드 대역 차단 · 국외 IP 관찰 · 로그인 이력 분류를 한 페이지에서 점검합니다. 주기 칩으로 거르고, 쿼리는 복사해서 바로 실행하세요.

출처 ① 로그인·메뉴 IP 차단 운영 가이드 §6 출처 ② 국외 IP 차단 구축 가이드 §14 출처 ③ 고속 분류 쿼리 (2026.08.28)
전체 일일 주간 월간 수시·장애

1 · 일일 점검

아침에 한 번. 어제~오늘 실제로 차단된 건과, 관찰 모드로 쌓인 국외 접속 이력을 확인합니다.

오늘 차단된 로그인 (클라우드·계정+IP 차단)

Daily

트리거 R98이 실제로 막은 건. 예상 밖 계정이 있으면 대역 오탐부터 의심합니다.

TB_WB_LOGIN_HIST_CHK
SELECT A.PROC_DT, A.USER_ID, A.LOGIN_IP, FN_GET_REAL_IP(A.LOGIN_IP) AS REAL_IP,
       FN_GET_CLOUD_IP_LABEL(A.LOGIN_IP) AS CLOUD, A.STAT_CD, A.BRWSR_INFO
FROM   TB_WB_LOGIN_HIST_CHK A
WHERE  A.PROC_FG IN ('I','U')
AND    A.PROC_DT >= TO_CHAR(SYSDATE, 'YYYYMMDD')
ORDER  BY A.PROC_DT DESC;
→CLOUD가 NULL인데 차단됐다면 계정+IP 확정 차단(C_HARD_LIST) 건. 국내 통신사 IP에 CLOUD 라벨이 찍히면 대역 오탐 — C_CIDR_LIST에서 제거.

오늘 쌓인 국외 접속 관찰 이력

Daily

관찰 모드(C_BLOCK_MODE='N')에서 차단 대상으로 판정돼 MONITOR로 기록된 건. 차단 전환 시 이 사람들이 막힙니다.

TB_WB_LOGIN_HIST_BLOCK
SELECT A.PROC_DT, A.PROC_FG, A.USER_ID, A.REAL_IP, A.COUNTRY_CODE, A.BLOCK_REASON
FROM   TB_WB_LOGIN_HIST_BLOCK A
WHERE  A.PROC_DT >= TO_CHAR(SYSDATE, 'YYYYMMDD')
ORDER  BY A.PROC_DT DESC;
→정당한 해외 사용자(출장·해외법인)는 TB_CM_IP_ALLOW에 승인 절차와 함께 등록. COUNTRY_CODE가 NULL이면 사설 IP 유입 후보 — 아래 국외 IP 점검의 오탐 쿼리로 확인.

2 · 주간 점검

주 1회. 클라우드 대역 접속 추이와 감시 후보 계정을 찾습니다.

최근 7일 클라우드 대역 로그인 (차단 여부 무관)

Weekly

AWS·GCP·HostRoyale 대역에서 온 모든 시도. 감시 대상이 아닌 계정의 반복 접속을 잡아냅니다.

TB_WB_LOGIN_HIST
SELECT A.LOGIN_DATE, A.USER_ID, A.LOGIN_IP,
       FN_GET_CLOUD_IP_LABEL(A.LOGIN_IP)            AS CLOUD,
       FN_CHK_BLOCK_TARGET_USER_YN(A.USER_ID)       AS TARGET_YN,
       FN_CHK_LOGIN_IP_BLOCK(A.USER_ID, A.LOGIN_IP) AS BLOCK_NOW
FROM   TB_WB_LOGIN_HIST A
WHERE  A.LOGIN_DATE >= TO_CHAR(TRUNC(SYSDATE) - 7, 'YYYYMMDD')
AND    FN_GET_CLOUD_IP_LABEL(A.LOGIN_IP) IS NOT NULL
ORDER  BY A.LOGIN_DATE DESC, A.LOGIN_DT DESC;
→TARGET_YN='N'인데 클라우드 IP가 반복되면 C_TARGET_USERS 추가 검토. 날짜 필터는 컬럼 가공 없는 문자열 비교로 바꿔 인덱스를 타도록 수정한 버전입니다.

계정·IP별 접속 집계 — 감시 후보 찾기

Weekly

최근 7일간 50회 이상 접속한 계정+IP 조합. 잦은 접속의 임시 차단(C_TEMP_LIST) 후보를 고릅니다.

TB_WB_LOGIN_HIST
SELECT A.USER_ID, FN_GET_REAL_IP(A.LOGIN_IP) AS REAL_IP, COUNT(*) CNT,
       MIN(A.LOGIN_DATE) FIRST_DT, MAX(A.LOGIN_DATE) LAST_DT,
       FN_GET_CLOUD_IP_LABEL(A.LOGIN_IP) AS CLOUD
FROM   TB_WB_LOGIN_HIST A
WHERE  A.LOGIN_DATE >= TO_CHAR(TRUNC(SYSDATE) - 7, 'YYYYMMDD')
GROUP  BY A.USER_ID, FN_GET_REAL_IP(A.LOGIN_IP), FN_GET_CLOUD_IP_LABEL(A.LOGIN_IP)
HAVING COUNT(*) >= 50
ORDER  BY CNT DESC;
→국내 통신사 IP는 절대 대역(C_CIDR_LIST)에 넣지 않습니다. 특정 계정만 문제면 C_TEMP_LIST에 쌍으로.

1분 60회 초과로 막힌 메뉴 호출

Weekly

감시 대상 계정의 과호출 차단 이력. 급증하면 스크립트성 접근을 의심합니다.

TB_WB_LOGIN_HIST_CHK
SELECT A.PROC_DT, A.USER_ID, A.LOGIN_IP
FROM   TB_WB_LOGIN_HIST_CHK A
WHERE  A.PROC_FG = 'C' AND A.BRWSR_INFO LIKE '60%'
AND    A.PROC_DT >= TO_CHAR(SYSDATE - 1, 'YYYYMMDD')
ORDER  BY A.PROC_DT DESC;
→동일 계정이 매일 걸리면 C_HARD_LIST 승격 또는 계정 소유자 확인.

3 · 국외 IP 점검 (관찰 모드)

차단 전환(C_BLOCK_MODE 'N'→'Y') 전에 돌리는 오탐 점검 세트. 관찰 기간 1~2주 동안 주기적으로 확인합니다.

SMS 등록/미등록 구분 집계 — 차단 전환 영향 범위

Weekly

C_CHK_TARGET을 'S'로 좁힐지 'A'로 갈지 판단하는 근거. [SMS=Y] 건이 차단 1순위 영향권입니다.

TB_WB_LOGIN_HIST_BLOCK
SELECT CASE WHEN BLOCK_REASON LIKE '%[SMS=Y]%' THEN 'SMS등록' ELSE '미등록' END AS SMS_DIV
,      COUNT(*)                AS CNT
,      COUNT(DISTINCT USER_ID) AS USER_CNT
FROM   TB_WB_LOGIN_HIST_BLOCK
GROUP  BY CASE WHEN BLOCK_REASON LIKE '%[SMS=Y]%' THEN 'SMS등록' ELSE '미등록' END;
→권장 전환 순서: N+A(현재, 전체 관찰) → [SMS=Y] 검토·정당 사용자 허용테이블 등재 → Y+S(등록자 차단) → Y+A(전체 차단).

차단 예정 건 집계 — 국가별 오탐 점검

Weekly

차단 전환 시 막힐 사용자·IP·국가 목록. 정당한 사용자를 여기서 걸러 허용테이블로 옮깁니다.

TB_WB_LOGIN_HIST_BLOCK
SELECT USER_ID, REAL_IP, COUNTRY_CODE
,      COUNT(*)        AS CNT
,      MIN(LOGIN_DATE) AS FIRST_TRY
,      MAX(LOGIN_DATE) AS LAST_TRY
FROM   TB_WB_LOGIN_HIST_BLOCK
GROUP  BY USER_ID, REAL_IP, COUNTRY_CODE
ORDER  BY CNT DESC;
→출장자·해외법인은 TB_CM_IP_ALLOW에 USER_ID+IP+기간+승인자로 등록. 차단된 로그인은 TB_WB_LOGIN_HIST에 남지 않으므로(롤백) 전환 후 추적은 이 BLOCK 테이블 기준.

사설 IP·매칭 실패 건 — 내부망 오탐 후보

Weekly

COUNTRY_CODE가 NULL인 건은 GeoIP에 없는 IP(사설·미할당)입니다. 차단 전환 전 반드시 비워야 합니다.

TB_WB_LOGIN_HIST_BLOCK
SELECT USER_ID, REAL_IP, COUNT(*) AS CNT
FROM   TB_WB_LOGIN_HIST_BLOCK
WHERE  COUNTRY_CODE IS NULL
GROUP  BY USER_ID, REAL_IP
ORDER  BY CNT DESC;
→10.x / 172.16~31.x / 192.168.x가 보이면 내부망 유입 — 허용테이블 등록 또는 사설 대역 예외 정책을 먼저 결정하고 전환.

4 · LOGIN_IP 분류 조회 — 고속판

국내 / 국외 / 차단대역(클라우드)을 한 번에 보는 쿼리. 함수를 행마다 부르지 않고 고유 IP·계정당 1번만 호출해 원판보다 크게 빠릅니다.

상세 조회 — 최근 7일, 국내 일반 IP 제외

Fast수시

건별로 실제 IP·국내여부·클라우드 라벨·분류를 표시. 전체를 보려면 마지막 WHERE 한 줄만 삭제.

TB_WB_LOGIN_HIST + IS_KOREA_IP / FN_GET_CLOUD_IP_LABEL
WITH H AS (
    SELECT A.LOGIN_DATE, A.LOGIN_DT, A.USER_ID, A.LOGIN_IP
    FROM   TB_WB_LOGIN_HIST A
    WHERE  A.LOGIN_DATE >= TO_CHAR(TRUNC(SYSDATE) - 7, 'YYYYMMDD')  -- 컬럼 가공 없이 (인덱스)
),
IPS AS (    -- IP 판정: 고유 IP당 1번
    SELECT /*+ MATERIALIZE */
           LOGIN_IP
    ,      FN_GET_REAL_IP(LOGIN_IP)              AS REAL_IP
    ,      IS_KOREA_IP(FN_GET_REAL_IP(LOGIN_IP)) AS KOREA_YN
    ,      FN_GET_CLOUD_IP_LABEL(LOGIN_IP)       AS CLOUD_LABEL
    ,      IP_TO_NUM(FN_GET_REAL_IP(LOGIN_IP))   AS IP_NUM
    FROM   (SELECT DISTINCT LOGIN_IP FROM H)
),
USERS AS (  -- 계정 판정: 고유 USER_ID당 1번 (직원테이블 COUNT가 여기서만 실행)
    SELECT /*+ MATERIALIZE */
           USER_ID
    ,      FN_CHK_BLOCK_TARGET_USER_YN(USER_ID) AS TARGET_YN
    FROM   (SELECT DISTINCT USER_ID FROM H)
)
SELECT H.LOGIN_DATE, H.LOGIN_DT, H.USER_ID, H.LOGIN_IP
,      I.REAL_IP, I.KOREA_YN, I.CLOUD_LABEL
,      CASE
           WHEN I.CLOUD_LABEL IS NOT NULL THEN '차단대역(' || I.CLOUD_LABEL || ')'
           WHEN I.KOREA_YN = 'Y'          THEN '국내'
           WHEN I.IP_NUM IS NULL          THEN '판정불가(형식오류/IPv6)'
           ELSE '국외/사설·미할당'
       END                               AS IP_CLASS
,      U.TARGET_YN
FROM   H
JOIN   IPS   I ON I.LOGIN_IP = H.LOGIN_IP
JOIN   USERS U ON U.USER_ID  = H.USER_ID
WHERE  NOT (I.KOREA_YN = 'Y' AND I.CLOUD_LABEL IS NULL)  -- 국내 일반 IP 제외 (전체 보려면 삭제)
ORDER  BY H.LOGIN_DATE DESC, H.LOGIN_DT DESC;
→IS_KOREA_IP에는 반드시 FN_GET_REAL_IP를 거친 IP를 넣습니다. XFF 체인 원본을 넣으면 맨 앞 사내 프록시(10.x)로 판정됩니다.

분류별 요약 집계 — 국내/국외/차단대역 분포

Fast수시

긴 기간을 볼 때는 상세 대신 이 집계를 사용. 분류별 로그인 수·계정 수·IP 수.

TB_WB_LOGIN_HIST
WITH H AS (
    SELECT A.USER_ID, A.LOGIN_IP
    FROM   TB_WB_LOGIN_HIST A
    WHERE  A.LOGIN_DATE >= TO_CHAR(TRUNC(SYSDATE) - 7, 'YYYYMMDD')
),
IPS AS (
    SELECT /*+ MATERIALIZE */
           LOGIN_IP
    ,      FN_GET_REAL_IP(LOGIN_IP)              AS REAL_IP
    ,      IS_KOREA_IP(FN_GET_REAL_IP(LOGIN_IP)) AS KOREA_YN
    ,      FN_GET_CLOUD_IP_LABEL(LOGIN_IP)       AS CLOUD_LABEL
    ,      IP_TO_NUM(FN_GET_REAL_IP(LOGIN_IP))   AS IP_NUM
    FROM   (SELECT DISTINCT LOGIN_IP FROM H)
)
SELECT CASE
           WHEN I.CLOUD_LABEL IS NOT NULL THEN '차단대역(' || I.CLOUD_LABEL || ')'
           WHEN I.KOREA_YN = 'Y'          THEN '국내'
           WHEN I.IP_NUM IS NULL          THEN '판정불가(형식오류/IPv6)'
           ELSE '국외/사설·미할당'
       END                          AS IP_CLASS
,      COUNT(*)                     AS LOGIN_CNT
,      COUNT(DISTINCT H.USER_ID)    AS USER_CNT
,      COUNT(DISTINCT I.REAL_IP)    AS IP_CNT
FROM   H
JOIN   IPS I ON I.LOGIN_IP = H.LOGIN_IP
GROUP  BY CASE
           WHEN I.CLOUD_LABEL IS NOT NULL THEN '차단대역(' || I.CLOUD_LABEL || ')'
           WHEN I.KOREA_YN = 'Y'          THEN '국내'
           WHEN I.IP_NUM IS NULL          THEN '판정불가(형식오류/IPv6)'
           ELSE '국외/사설·미할당'
       END
ORDER  BY LOGIN_CNT DESC;
→기간을 30일 이상으로 늘릴 때도 이 구조면 함수 호출이 고유 IP 수만큼만 늘어 부담이 적습니다.

5 · 수시 · 장애 대응

"로그인이 안 된다"는 문의가 오면 이 순서로. 에러 메시지에 Login Blocked가 있어야 이 시스템이 막은 것입니다.

단건 즉석 판정 — 왜 막혔나

수시

에러 메시지의 계정·IP를 넣고 한 번에 판정. 공용 함수는 전부 읽기 전용이라 안심하고 호출.

DUAL
SELECT FN_GET_REAL_IP('에러메시지의IP')                    AS REAL_IP
,      FN_GET_CLOUD_IP_LABEL('에러메시지의IP')             AS CLOUD      -- NULL 아니면 대역 차단
,      IS_KOREA_IP(FN_GET_REAL_IP('에러메시지의IP'))       AS KOREA_YN   -- N 이면 국외
,      FN_CHK_BLOCK_TARGET_USER_YN('계정')                 AS TARGET     -- Y 면 감시 대상
,      FN_CHK_LOGIN_IP_BLOCK('계정', '에러메시지의IP', 'Y') AS RESULT   -- N=차단 / T=임시 / Y=허용
,      IS_LOGIN_ALLOWED('계정', FN_GET_REAL_IP('에러메시지의IP')) AS GEO_ALLOW -- 국외차단 관점
FROM   DUAL;
→RESULT='N'이면 IP 차단. 'Y'인데도 막히면 ① 1분 60회 초과 → ② 메뉴 함수 URL 규칙 → ③ 국외 IP(GEO_ALLOW='N') 순으로 확인. 국외 IP 차단은 로그인(R90) · 메뉴(STEP 7) · SMS 인증(FN_GET_TB_CM_SMS_VFC_CODE C10~C21) 세 곳 공통 — 인증번호 화면에서 '05|허용되지 않은 국가(IP)' 메시지가 떴다면 이 판정입니다. 메뉴·SMS 쪽은 p_log_yn='N'(판정만)이라 BLOCK 이력이 남지 않으니 이력이 없다고 차단이 없었던 게 아닙니다.

현재 감시 대상 전체 명단

수시

본사·매장 코드 소속 + 개별 지정 계정의 합집합이 전체 감시 대상입니다.

TB_HQ_EMPLOYEE / TB_MS_EMPLOYEE
SELECT A.USER_ID, 'HQ:' || A.HQ_OFFICE_CD AS SRC FROM TB_HQ_EMPLOYEE A WHERE A.HQ_OFFICE_CD IN ('H0268','DS001')
UNION ALL
SELECT A.USER_ID, 'MS:' || A.STORE_CD     AS SRC FROM TB_MS_EMPLOYEE A WHERE A.STORE_CD     IN ('DS00001','DS00002');
-- 여기에 C_TARGET_USERS 4개(h0268, momse09686, kjsun1117, kjsun11177)를 더한 것이 전체
→큰 본사·매장 코드를 추가하기 전에 명단 크기 확인 — 감시 대상은 메뉴 클릭마다 이력 INSERT + 60회 제한 + 화면 딜레이를 받습니다.

배포 후 INVALID 객체 확인

수시

상수 목록을 고치고 재컴파일한 직후 반드시 실행. 전부 VALID여야 합니다.

USER_OBJECTS
SELECT OBJECT_NAME, OBJECT_TYPE, STATUS
FROM   USER_OBJECTS

                        'FN_CHK_BLOCK_TARGET_USER_YN','FN_CHK_LOGIN_IP_BLOCK',
                        'FN_GET_MENU_CHK_YN2','TR_TB_WB_LOGIN_HIST_R98',

                        'TR_TB_WB_LOGIN_HIST_R90','FN_GET_TB_CM_SMS_VFC_CODE');

→배포 직후 로그인이 전부 실패하면 즉시 이전 버전으로 롤백 컴파일. 트리거 WHEN OTHERS가 -20002로 전체 로그인을 막을 수 있습니다.

6 · 월간

이력 테이블 정리와 GeoIP 재적재 후 확인.

메뉴 클릭 이력 정리 (30일 이전)

Monthly

PROC_FG='C'(메뉴 클릭)만 정리. 1분 카운트는 최근 1분만 쓰므로 삭제해도 판정에 영향 없습니다.

TB_WB_LOGIN_HIST_CHK
DELETE FROM TB_WB_LOGIN_HIST_CHK
WHERE  PROC_FG = 'C'
AND    PROC_DT < TO_CHAR(SYSDATE - 30, 'YYYYMMDD');
COMMIT;
-- I/U(로그인 차단 이력)는 보안 감사용 — 별도 보관 정책에 따를 것
→감시 대상 계정이 늘면 증가 속도도 늘어납니다. 정리 전 건수를 한 번 확인하세요.

GeoIP 재적재 후 확인 — 시노님·건수·통계

Monthly

월간 재적재 후: 건수 검증 → 통계수집 → 시노님 스위치 순서를 지켰는지 확인.

TB_CM_GEOIP_RANGE
-- 현재 시노님이 가리키는 테이블
SELECT table_name FROM user_synonyms WHERE synonym_name = 'TB_CM_GEOIP_RANGE';

-- 건수 (보통 30~50만 행)
SELECT COUNT(*) FROM TB_CM_GEOIP_RANGE;

-- 인덱스 상태 (DIRECT=TRUE 적재 후 UNUSABLE 확인)
SELECT index_name, status FROM user_indexes WHERE table_name LIKE 'TB_CM_GEOIP_RANGE_%';

-- 판정 속도 샘플 (즉시 응답이어야 정상 — 느리면 통계수집 누락 의심)
SELECT IS_KOREA_IP('223.62.180.1') FROM DUAL;  -- 'Y'
SELECT IS_KOREA_IP('8.8.8.8')      FROM DUAL;  -- 'N'
→조회가 수 초 걸리면 DBMS_STATS.GATHER_TABLE_STATS 누락. 통계수집 후 재확인.

점검 시 하지 말 것

  • FN_CHK_LOGIN_BLOCK을 SELECT 점검에 쓰지 않는다 — 차단 대상 판정 시 AUTONOMOUS로 이력을 INSERT하는 함수라, 점검하는 것만으로 TB_WB_LOGIN_HIST_BLOCK에 행이 쌓입니다. 점검은 읽기 전용 함수(IS_KOREA_IP, FN_GET_CLOUD_IP_LABEL, FN_CHK_LOGIN_IP_BLOCK 등)만 사용.
  • FN_GET_TB_CM_SMS_VFC_CODE도 SELECT 테스트에 주의 — AUTONOMOUS 함수라 C10/C20은 호출 즉시 인증번호가 실제 저장·발송되고, C11/C21은 실패 카운트가 올라갑니다. 점검용 호출은 조회성인 CHK/CDI만.
  • 날짜 필터에서 컬럼을 가공하지 않는다 — TO_DATE(LOGIN_DATE,…) >= …는 인덱스를 못 탑니다. LOGIN_DATE >= TO_CHAR(…) 형태로.
  • "국내 제외" WHERE는 속도와 무관 — 국내 판정 자체가 함수 호출이라 필터에 넣어도 호출 횟수는 같습니다. 속도는 고유 IP당 1번 호출 구조(4번 그룹)로 해결.
  • 국내 통신사 대역을 C_CIDR_LIST에 넣지 않는다 — 가입자 회선이라 정상 매장이 통째로 차단됩니다. 특정 계정만 문제면 C_TEMP_LIST에 쌍으로.
  • 기간 필터 없이 전체 이력에 함수 쿼리를 돌리지 않는다 — 긴 기간은 요약 집계 쿼리로.
